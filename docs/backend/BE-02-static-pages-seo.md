# BE-02 — Static Pages SEO Management

## Цель
Реализовать первый законченный вертикальный срез: MariaDB → Laravel 13 → Filament 5 → публичный API → серверные metadata Next.js. После проверки SEO семи статических страниц управляется исключительно из Filament, без молчаливого fallback на mock.

## Контекст
Изучить `BE-01-backend-architecture-audit-report.md` и актуальный репозиторий. Не считать предложенные в аудите сущности уже реализованными. Стек: Next.js App Router, Laravel 13, Filament 5, MariaDB, Docker. Сохранить существующий UI и SEO-содержимое.

## Объём
Фиксированный whitelist ключей и путей:
- `home` → `/`
- `shop` → `/shop`
- `solutions` → `/solutions`
- `catalogues` → `/catalogues`
- `about` → `/about`
- `contacts` → `/contacts`
- `private_policy` → `/private-policy`

Не включать динамические категории, товары, `/news/[slug]`, корзину, поиск. `/news` — отдельная статическая индексная страница, но пока не включать без явного решения; в отчёте отметить этот пропуск и предложить добавить её в следующем расширении. Не менять существующую SEO-логику динамических страниц.

## 1. Сохранение исходных значений
До редактирования составить таблицу существующих metadata каждой из семи страниц: title, description, Open Graph, Twitter, robots, canonical, наследование root layout. Получать фактические значения из исходников, а не придумывать новые. Зафиксировать в отчёте. Если значение наследуется, сохранить фактический результат. Не заменять текущие тексты «улучшенными» без запроса.

## 2. MariaDB / Laravel
Создать таблицу `page_seo` (или `page_seos`, согласно конвенции Laravel, с явным обоснованием) с полями `id`, `page_key` UNIQUE, `title`, `description`, `og_image_path` nullable, timestamps. Хранить путь/ссылку на управляемый публичный медиафайл безопасно; не строить ради одного поля глобальную media-assets подсистему. Допустим вариант `og_media_id` только если общая медиа-модель уже реализована. Валидация: ключ из whitelist; непустые title/description, разумные максимумы; допустимые изображения JPEG/PNG/WebP, проверка MIME и размера. Рекомендовать 1200×630, но не требовать ровно эти размеры.

Идемпотентно и без перезаписи редакторских изменений заполнить семь записей существующими значениями. Seeder/команда при повторном запуске добавляет отсутствующие ключи, не сбрасывает отредактированные поля. Существующие значения title/description сохраняются точно. Миграции обратимы; не выполнять destructive операции на существующих данных.

## 3. Filament
Раздел `SEO` → `Static Pages` или `Page SEO`: список ровно семи предопределённых страниц с названием, URL, SEO title, датой обновления. Разрешено редактирование; создание, удаление и изменение page_key/URL запрещены. Доступ только авторизованным администраторам согласно текущей политике. Поля: SEO Title, Meta Description, OG Image (upload/preview/remove), readonly Canonical URL. Счётчики символов для title/description, подсказки по рекомендуемой длине без искусственного запрета валидного текста.

### Общий компонент Google Search Preview — ОБЯЗАТЕЛЬНО
Сделать переиспользуемый Filament компонент/fieldset/view, например `SeoSearchPreview`, с явным API для получения реактивных значений `title`, `description`, `canonicalUrl`/`displayUrl`. Он должен обновляться без сохранения формы, корректно обрезать длинные тексты визуально, поддерживать перенос строк и мобильную ширину. Визуализация: URL → синий кликабельный на вид, но не обязательно реально кликабельный заголовок → серое описание. Не использовать реальный Google логотип и не обещать точный сниппет. Подпись: `Preview only — Google may rewrite titles and descriptions.`

Компонент не должен зависеть от модели `PageSeo`; позже его можно подключить к ProductResource, CategoryResource, NewsArticleResource. Избегать копирования preview-разметки между формами. Поддерживать пустые поля и корректное экранирование пользовательского текста (никакого raw HTML/XSS). Не добавлять тяжёлые зависимости.

## 4. API
`GET /api/v1/page-seo/{pageKey}` — только whitelist, JSON `{ "data": { "pageKey": "about", "title": "...", "description": "...", "ogImageUrl": "https://..." | null } }`. 404 для неизвестного ключа, 503/500 при реальной ошибке. Публичный read-only endpoint без admin auth, без сессионных cookies и утечки внутренних путей. Canonical не редактируется и вычисляется в Next.js по фиксированному маршруту.

Кеш: для первого вертикального среза предпочтительнее `no-store` для гарантированного немедленного эффекта правки; если выбирается кеш, реализовать явную инвалидизацию после сохранения в Filament и доказать тестом, что правка становится видна. Никакого бесконечно устаревающего Next.js static build. Учитывать сборку и режим runtime rendering для каждой страницы.

## 5. Next.js
Для каждой из семи страниц metadata берутся через серверный helper из Laravel API (`API_INTERNAL_URL` / существующий server HTTP helper). Использовать `generateMetadata` или иной корректный серверный механизм App Router, не загружать SEO через клиентские эффекты. Выдавать `title`, `description`, `alternates.canonical`, `openGraph`, `twitter` с учетом существующих robots и иных метаданных. Не менять JSON-LD, структуру контента, H1, Header/Footer, формы или логику страниц.

Использовать production origin из существующей конфигурации `metadataBase`, а не hardcode staging-домена. Для Home добавить корректный canonical `/`. OG image URL должен быть доступен извне, а не содержать внутренний Docker hostname. Если изображения нет, сохранить разумное существующее наследование/поведение OG image, не вставлять сломанный URL.

После переключения не использовать локальные title/description как fallback при отказе API: ошибку наблюдаемо логировать (без секретов), не маскировать как 404. Допускается явная стратегия доступности на согласование, но не скрытое использование устаревшего mock. Не допускать дублирующих или конфликтующих metadata из layout и page.

## 6. Проверки и тесты
- Seeder повторно запускается без перезаписи отредактированного SEO.
- Только семь допустимых page_key, администратор не может создать/удалить запись или изменить ключ.
- API: корректный JSON, 404 для чужого ключа, отсутствие внутренних полей.
- Изменить title и description у `/about` в Filament → перезагрузить страницу → новые значения видны в серверном HTML, а не только после hydration.
- OG image загрузить/заменить/удалить; URL работает публично и metadata корректны.
- Проверить каждую из семи страниц, canonical, robots и Open Graph/Twitter; главная имеет canonical.
- Search Preview реактивен до сохранения, безопасен к HTML-строкам, адаптивен.
- Ошибка API не приводит к тихому fallback или `notFound`.
- Laravel tests, TypeScript, Next.js production build; ручная проверка desktop/mobile и сохранения существующего интерфейса.
- Если что-то нельзя проверить в текущем окружении, честно указать это в отчёте.

## Ограничения
Не реализовывать товары, категории, News, Solutions, заявки, PDF или универсальную CMS. Не менять дизайн публичных страниц, не подключать новые крупные пакеты. Не запускать миграции на production без отдельного подтверждения. Соблюдать уже существующую авторизацию Filament и маршрутизацию nginx `/api`.

Отдельно указать, что `/news` как индексный URL пока не включён в whitelist и требует решения.
