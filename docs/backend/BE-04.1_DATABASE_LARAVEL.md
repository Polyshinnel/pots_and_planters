# BE-04.1 — PDF Catalogues: Database + Laravel

**Проект:** Pots & Planters 2.0  
**Статус:** ТЗ согласовано к реализации; код этапа не проверен  
**Область:** только MariaDB, Laravel 13 и backend-тесты. Filament, публичный API и Next.js — следующие этапы.

## 1. Цель

Создать надёжную backend-основу для PDF-каталогов: схему данных, Eloquent-модель, связь many-to-many с существующими категориями, инварианты публикации и безопасную стратегию хранения/замены файлов. Не менять существующий публичный сайт.

## 2. Исходные сведения (по read-only аудиту)

- Категории уже реализованы через MariaDB → Laravel → Filament → API → Next.js, имеют внутренние PK, стабильные `public_id`, slug, публикацию и сортировку.
- Идентификаторы фильтра категорий: `outdoor`, `indoor`, `artificial`; URL-slugs: `outdoor-pots`, `indoor-pots`, `artificial-plants`.
- Каталоги пока существуют только во frontend mock (`frontend/src/lib/catalog/repository.ts`, `catalogues.mock.ts`, `frontend/src/types/catalog.ts`). Backend-модели, таблиц и API каталогов пока нет.
- В рабочем дереве есть незакоммиченные правки, включая `CategoryResource.php`. Их обязательно сохранить.
- PDF будут приватными, обложки — публичными; контролируемая выдача PDF после заявки относится к BE-07.

## 4. Схема данных

### `catalogues`

Создать миграцию в стиле существующего backend:

| Поле | Требование |
| --- | --- |
| `id` | Внутренний PK, тип согласовать с действующими таблицами |
| `public_id` | Стабильный уникальный публичный идентификатор; генерация на backend, формат согласовать с существующими сущностями |
| `slug` | Уникальный, непустой, пригодный для URL |
| `title` | Непустое название |
| `description` | Nullable текст |
| `pdf_path` | Nullable путь на **приватном** диске; без публичного URL |
| `cover_path` | Nullable путь на публичном диске |
| `cover_alt` | Nullable alt-текст |
| `status` | `draft`, `published`, `archived`; по умолчанию `draft` |
| `sort_order` | Целое число, по умолчанию 0; индекс при необходимости |
| `created_at`, `updated_at` | Timestamps |

Не добавлять выдуманные PDF, обложки, каталоги, SEO-поля, цены и характеристики. Уточнить длины полей, способ генерации `public_id` и хранение enum/status по принятому стилю репозитория; не вводить лишние зависимости.

### `catalogue_category`

- `catalogue_id` и `category_id` — FK на **внутренние PK**, с типами, точно совпадающими с реальными таблицами.
- Уникальность пары, исключающая дубликаты.
- Корректные ограничения и каскадное удаление связей при удалении каталога; поведение удаления категории согласовать с существующими правилами проекта.
- Не хранить `public_id` или slug в pivot.

## 5. Eloquent и доменные правила

- Создать модель `Catalogue` с явными разрешёнными полями/casts и `belongsToMany(Category::class)`; добавить обратное отношение в `Category`, минимально изменив существующий файл и не затрагивая `CategoryResource.php`.
- Обеспечить уникальность slug и `public_id` на уровне БД; повторное сохранение записи не должно менять `public_id`.
- Публикация допустима только при наличии непустых `pdf_path`, `cover_path` и хотя бы одной существующей категории. Проверка должна быть серверной и не зависеть от будущего Filament; продумать атомарность проверки и синхронизации pivot в рамках транзакции.
- Для `draft` и `archived` разрешить неполные данные. При удалении последней категории или обязательного файла у опубликованного каталога нельзя оставлять некорректное состояние `published`.
- Зафиксировать понятный сервисный/доменный интерфейс сохранения каталога и синхронизации категорий, чтобы следующие этапы использовали единые правила, без избыточной абстракции.
- Если внешние прямые изменения модели могут обойти сервис, явно описать границу гарантий и обеспечить инвариант на предусмотренных путях записи. Не заявлять о полной защите на уровне БД, если она не реализована.

## 6. Файлы и безопасность

- PDF — на приватном Laravel filesystem disk без публичной раздачи и без `storage:link` для PDF. Обложки — на публичном диске.
- Пути относительные, безопасные, без доверия пользовательским абсолютным путям; на данном этапе не создавать публичный endpoint скачивания.
- Предусмотреть операции замены и удаления: новый файл сохраняется/валидируется до смены ссылки в БД; старый удаляется **после успешного commit** и только если больше нигде не используется. При ошибке сохранения не терять предыдущий файл; новые неиспользованные файлы подлежат уборке.
- Не удалять файлы, используемые другими записями. В явном виде описать, где будет находиться lifecycle-логика загрузок Filament в BE-04.2, если в BE-04.1 нет самого uploader.
- Не выдавать приватные пути в логах или публичных ответах. Реальную доставку PDF отложить до BE-07.

## 7. Что реализовать сейчас

1. Миграции `catalogues` и `catalogue_category` с индексами и FK.
2. `Catalogue` и минимальное обратное отношение в `Category`.
3. Минимальный backend-механизм валидации и атомарной смены статуса/категорий, пригодный для использования в BE-04.2.
4. Конфигурацию приватного диска — только если в проекте нет подходящего существующего.
5. Backend-тесты для схемы, отношений, идентификаторов, правил публикации, транзакционной согласованности и важных негативных сценариев.

**Не реализовывать:** Filament Resource, HTTP endpoint `/api/v1/catalogues`, frontend-адаптер, изменение публичного дизайна, скачивание PDF, импорт фиктивных данных, production-миграции.

## 8. Проверки и критерии приёмки

- [ ] Миграции применяются и откатываются на **локальной/тестовой** БД; FK и уникальные индексы работают.
- [ ] `public_id` стабилен и уникален; slug уникален.
- [ ] Один каталог связан с несколькими категориями, повторная привязка не создаёт дубликат.
- [ ] `draft` сохраняется без файлов и категорий; `published` без PDF, обложки или категории отклоняется.
- [ ] Нельзя незаметно сделать опубликованный каталог неполным при предусмотренных операциях обновления.
- [ ] Ошибка при сохранении не оставляет частично обновлённые связи/статус.
- [ ] PDF не доступен через публичный storage URL; обложка может храниться публично.
- [ ] Проверены сценарии безопасной замены/очистки файлов в пределах реально реализованной логики; незавершённые части чётко переданы BE-04.2.
- [ ] Запущены соответствующие backend-тесты, результаты указаны; при невозможности запуска это явно отмечено.
- [ ] Не изменены `CategoryResource.php`, frontend, существующие маршруты и SEO; исходные незакоммиченные правки сохранены.
- [ ] Нет production-миграций и выдуманных данных.
