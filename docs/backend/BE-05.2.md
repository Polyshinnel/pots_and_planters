# BE-05.2 — News: MariaDB, Laravel и публичный API

**Проект:** Pots & Planters 2.0  
**Статус:** ТЗ согласовано к передаче Codex; реализация не подтверждена  
**Область:** Backend, без Filament UI и Next.js  
**Основание:** `PROJECT_CONTEXT.md`, `ROADMAP.md`, read-only аудит BE-05.1 и согласованные решения после аудита.

## Цель

Подготовить backend-основу News: управляемые категории, публикации, безопасное хранение rich text, типизированные публичные API `/api/v1/news` и `/api/v1/news/{slug}`. Не импортировать исторические записи в рабочую БД на этом этапе.

## 0. Обязательная проверка перед изменениями

1. Прочитать `PROJECT_CONTEXT.md`, `ROADMAP.md`, результаты BE-05.1.
2. Проверить актуальный `git status`, модели, миграции, API routes, `CatalogueResource`, `CreateCatalogue`, DTO и тестовые соглашения. Не считать аудит гарантией неизменности репозитория.
3. Уточнить фактический формат хранения встроенного `Filament 5 RichEditor` и уже доступные средства очистки HTML. **Не реализовывать произвольный HTML sanitizer регулярными выражениями.** Если безопасного решения в имеющемся стеке нет — описать варианты и остановиться до согласования новой зависимости.
4. Сохранить ручные изменения и существующие API-контракты; не выполнять ненужный рефакторинг.

## 1. MariaDB — схема

Создать миграции (не выполнять на production):

### `news_categories`
- `id` — внутренний PK;
- `name` — обязательное название;
- `slug` — уникальный, kebab-case;
- `sort_order` — порядок;
- `is_active` — доступность категории;
- `created_at`, `updated_at`.

### `news_articles`
- `id` — внутренний PK;
- `public_id` — стабильный уникальный внешний ID по существующим соглашениям;
- `category_id` — FK на `news_categories`;
- `title`, `slug` (unique), `excerpt`;
- `body` — `longText`, безопасное HTML-содержимое RichEditor;
- `cover_path`, `cover_alt`;
- `og_image_path` — nullable override;
- `published_at` — `date`, без выдуманного времени;
- `status` — `draft`, `published`, `archived`;
- `seo_title`, `seo_description`;
- timestamps.

Индексы для публичной выборки и сортировки. Не вводить таблицы редиректов, конструктор блоков или связь с товарными категориями. Для News на первом этапе одна редакционная категория на статью.

## 2. Laravel — модели и правила

Создать `NewsArticle`, `NewsCategory` с relationships, casts, контролируемым mass assignment и scopes публичной видимости.

- Публичны только статьи `published` с активной категорией и валидными обязательными полями.
- Порядок: `published_at DESC` и стабильный вторичный ключ. Для исторических публикаций с датой `2025-10-30` сохранить действующий порядок №6 перед №7; не приписывать время публикации.
- Slug автоматически создаётся из title по фактическому паттерну PDF-каталогов, допускает ручную корректировку и изменение после публикации; уникальность проверяется на сервере.
- Не добавлять автоматические 301: индивидуальные перенаправления при необходимости настраиваются отдельно в Nginx.
- При публикации проверять title, slug, excerpt, body, category, дату, обложку, alt и обязательные SEO-поля. Draft допускает незаполненные поля в рамках обоснованной схемы валидации.
- При отсутствии активной категории публикация недопустима; существующие публикации такой категории скрываются публично.

## 3. Rich text и безопасность

Редактор на BE-05.3 — встроенный Filament RichEditor, **не** textarea с ручными блоками. На этом этапе подготовить совместимое хранение и безопасную серверную обработку.

- Поддержать абзацы, заголовки, списки, выделение и inline-ссылки.
- Очистка по allowlist тегов и атрибутов; запрещены `script`, `iframe`, обработчики событий, опасные URL-схемы и произвольный исполняемый HTML.
- URL ссылок валидировать; при открытии внешних ссылок в новой вкладке обеспечить `rel="noopener noreferrer"`.
- Не допускать двойного escaping, не доверять HTML из БД автоматически.
- Зафиксировать, на каком этапе выполняется очистка (при сохранении и/или перед выдачей), и покрыть тестами XSS-попытки.
- Сохранить текст и inline-ссылки всех семи исходных статей при будущем импорте.

## 4. Public API

Реализовать:

- `GET /api/v1/news` — опубликованные статьи, стабильная сортировка, JSON `{ "data": [...] }`;
- `GET /api/v1/news/{slug}` — опубликованная статья или `404`, JSON `{ "data": { ... } }`.

Использовать существующие соглашения Laravel API Controller + типизированный DTO. Контракт списка:

`id`, `slug`, `title`, `excerpt`, `category` (`name`, `slug`), `coverImage`, `coverAlt`, `publishedAt`, `seoTitle`, `seoDescription`.

Деталь дополнительно: `body`, `ogImage`.

Пути хранения файлов, внутренние ID, draft content, исходные filesystem paths и административные поля не раскрывать. Публичные изображения возвращать как корректные URL по существующему паттерну. Не менять API статического SEO для `/news`.

## 5. Исторические публикации — подготовка, не импорт

В исходном frontend семь публикаций за 2023–2025 годы. Подготовить возможность воспроизводимого импорта на следующем этапе, но **не запускать импорт**. Использовать только реальные тексты, даты, slug и SEO из `frontend/src/data/news.mock.ts`; для публикации INDEX 2025 каноническая обложка — `5_new.png`. Не переносить ошибочные подписи неиспользуемого `externalLinks` у статьи №2. Не создавать фиктивные публикации, изображения или метаданные.

## 6. Тестирование

Добавить backend Feature/Unit tests на:

1. Список опубликованных, фильтрацию draft/archived и неактивных категорий.
2. Стабильный порядок при одинаковой дате, включая требование №6 перед №7 при будущем импорте.
3. Деталь по slug и `404` для неизвестного/скрытого slug.
4. Форму публичного DTO, корректные URL и отсутствие утечек `*_path`.
5. Уникальность и автогенерацию slug, возможность ручной смены.
6. Валидацию перехода в published и связанной категории.
7. Rich text: допустимые форматирование/ссылки, XSS, опасные протоколы и отсутствие двойного escaping.

Тесты с `RefreshDatabase` запускать **только** через Docker backend и выделенную БД `potsandplanters_test` согласно правилам репозитория. Проверить `git diff --check`. Если тестовая среда недоступна — сообщить, не заявлять о прохождении тестов.
