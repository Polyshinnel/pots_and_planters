# BE-05.3 historical news import

`backend/database/fixtures/news/historical-news.json` is a checked-in snapshot generated directly from `frontend/src/data/news.mock.ts`. Its seven source IDs, titles, slugs, excerpts, typed body blocks, original dates, image filenames and alt text, categories, and SEO fields are copied from that source. The snapshot intentionally excludes the mock-only `externalLinks` metadata; inline body links remain part of the imported article. The corresponding unmodified image files are in `backend/database/fixtures/news/images/`, with SHA-256 hashes in the snapshot.

The importer converts paragraph and inline-link blocks to HTML, runs the existing `NewsHtmlSanitizer`, checks normalized text survives that conversion, validates all source images, and checks database conflicts before writing. Category labels map to kebab-case slugs: `Projects & Collaborations` → `projects-collaborations`, `Company News` → `company-news`, and `Events & Exhibitions` → `events-exhibitions`. Categories are created only when absent and are not updated on later runs.

Run a dry check (default; writes nothing):

```sh
docker compose -f compose.yaml -f compose.dev.yaml exec -T backend sh -lc 'DB_DATABASE=potsandplanters_test php artisan news:import-historical'
```

Apply only to the isolated test database:

```sh
docker compose -f compose.yaml -f compose.dev.yaml exec -T backend sh -lc 'DB_DATABASE=potsandplanters_test php artisan news:import-historical --apply'
```

The stable mapping is source `id` → `news_articles.public_id`, with slug as a conflict check for rows that have no matching public ID. Repeated runs skip a matching public ID and preserve all editorial fields and image choices. A different record using the source slug, an invalid fixture, or a missing/changed image aborts the run. Images are copied unchanged to the public disk under `news/`; no import occurs through migrations or normal seeders. The command refuses writes when Laravel reports the `production` environment.
