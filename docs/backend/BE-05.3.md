# BE-05.3 — News: Filament Management и импорт исторических публикаций

**Проект:** Pots & Planters 2.0  
**Статус:** ТЗ для Codex; реализация не подтверждена  
**Область:** Laravel 13 / Filament 5, категории, редактор публикаций, детерминированный импорт семи исторических статей. Без изменений публичного Next.js.  
**Зависимость:** BE-05.2 реализован и протестирован по отчёту Codex; перед работой проверить актуальный репозиторий.

## Цель

Дать редактору возможность управлять категориями и статьями News через Filament, создавать/редактировать rich text без ручного ввода блоков и перенести **все семь** существующих исторических публикаций из frontend mock без повторного ручного набора.

## 0. Обязательная проверка

1. Прочитать `PROJECT_CONTEXT.md`, `ROADMAP.md`, `docs/backend/BE-05.2.md` (если существует), аудит BE-05.1 (если доступен) и актуальный `git status`.
2. Проверить фактические `NewsArticle`, `NewsCategory`, `NewsHtmlSanitizer`, DTO, миграции, API, тесты, Filament Resources, `SeoSearchPreview`, паттерн создания slug у Catalogue.
3. Проверить реальные `frontend/src/data/news.mock.ts`, `frontend/src/types/news.ts`, `frontend/src/lib/news/repository.ts`, изображения `frontend/public/images/news/` и наличие всех семи исходных статей. Не считать описанную в аудите структуру неизменной.
4. Не затирать ручные изменения. Если несовместимость между HTML RichEditor, sanitizer и исходным форматом не позволяет сохранить содержание без потерь — остановиться, описать проблему и варианты, не выполнять частичный импорт.

## 1. Filament — категории News

Создать полноценный ресурс для `NewsCategory` с List/Create/Edit (по фактическим соглашениям Filament 5):

- Название, уникальный slug (автогенерация из name с ручным редактированием), `sort_order`, `is_active`.
- Таблица с названием, slug, активностью, сортировкой и удобными действиями.
- Серверная валидация уникальности и корректности slug; понятные ошибки.
- Не допускать опасного удаления категории с привязанными статьями; показать понятную ошибку/запрет. Отключение категории должно скрывать её статьи через существующую backend-логику, без удаления данных.
- Не связывать редакционные категории с категориями товаров или каталогов.

## 2. Filament — публикации News

Создать `NewsArticleResource` с List/Create/Edit и удобной редакционной формой:

- `title`, `slug`, `excerpt`, категория (выбор из NewsCategory), `published_at` как **дата без времени**, `status` (`draft`, `published`, `archived`).
- `body` — **встроенный Filament 5 RichEditor**, не textarea, не Builder/Reapeater абзацев. Формат хранения — совместимый с BE-05.2 (`longText` HTML), без несанкционированного переключения на JSON.
- Форматирование: абзацы, заголовки, списки, жирный/курсив и inline-ссылки — только то, что поддерживает существующий sanitizer. Отключить неподдерживаемые/опасные возможности, особенно HTML-вставки, embed, произвольные attachments, если они не согласованы.
- `cover_path` — загрузка публичного изображения через существующий FileUpload-паттерн; предпросмотр, alt. `og_image_path` — необязательная отдельная обложка для OG, с понятным fallback на cover в DTO, если уже предусмотрен.
- SEO: `seo_title`, `seo_description` и **тот же** `SeoSearchPreview` из BE-02, с URL `/news/{slug}`. Не дублировать компонент.
- Slug автоматически предлагается из title по проверенному паттерну Catalogue; редактор может исправить его вручную и менять у существующей статьи. Не перезаписывать ручное значение при последующем редактировании title. Проверять уникальность; не создавать автоматические redirects.
- Draft можно сохранять незавершённым; при переходе в published валидировать все обязательные поля согласно BE-05.2, включая активную категорию, дату, изображение/alt, SEO и непустое безопасное тело. Отображать ошибки в форме, не терять введённый текст.
- Таблица: заголовок, категория, статус, дата, slug, фильтры по категории/статусу и поиск по заголовку; сортировка, понятные действия.
- Избегать тяжёлых новых зависимостей и переписывания общего UI. Не изменять публичный дизайн.

## 3. Импорт семи исторических публикаций — обязательно в этом этапе

**Источник истины:** существующий frontend mock и его реальные локальные изображения, а не заново набранные или сгенерированные тексты.

1. Создать отдельную воспроизводимую Artisan-команду или безопасный специализированный импортёр, который читает проверенный snapshot исходных mock-данных. Не делать импорт побочным эффектом обычного `db:seed` или миграций. Если backend-контейнер не имеет доступа к frontend-исходникам, выбрать прозрачный перенос данных в версионируемый import fixture с документированным происхождением; не дублировать тексты вручную.
2. Сохранить **дословно** title, slug, excerpt/summary, body, inline-ссылки, даты (без выдуманного времени), SEO title/description и категорийные ярлыки из текущих mock. Учитывать исходные примечания об историчности, если они входят в отображаемый контент.
3. Сопоставить mock-категории с управляемыми `news_categories`. Создать только реально встречающиеся категории, с документированным отображением ярлыков в slug. Если обнаружено неоднозначное соответствие — остановить импорт до согласования.
4. Перевести существующие типизированные paragraph/inline link блоки в HTML, совместимый с RichEditor и `NewsHtmlSanitizer`. Проверить, что конвертация сохраняет порядок абзацев, ссылки, текст и не добавляет контент. Не импортировать ошибочные неиспользуемые подписи `externalLinks` у статьи №2.
5. Перенести изображения в используемый backend public disk/каталог по согласованному FileUpload-паттерну. Обеспечить доступность файлов через публичный URL, не отдавать локальные пути. Для INDEX использовать **`5_new.png`**, не `5.png`. Сохранять оригиналы без произвольного ресайза/замены. Alt переносить из проверенного источника; если обязательный alt отсутствует — остановиться и сообщить, не сочинять фактическое описание.
6. Сохранить оригинальные семь slug и даты. Две статьи от **2025-10-30** должны выводиться в прежнем порядке: №6 перед №7; если текущая сортировка BE-05.2 этого не гарантирует, зафиксировать проблему и предложить минимальную совместимую корректировку с тестом.
7. Импорт должен быть **идемпотентным**: повторный запуск не создаёт дубликатов категорий, статей и медиа; сопоставление по стабильному slug/ID с предсказуемым поведением. Не перезаписывать редакторские правки при повторном запуске без отдельного явного режима/подтверждения. Не удалять посторонние статьи.
8. Предусмотреть dry-run/проверку источников и отчёт: найдено, создано, пропущено, конфликты, ошибки, пути файлов, число категорий. При отсутствии файла, некорректном контенте, конфликте slug или несовместимом sanitizer — не делать вид, что импорт завершился успешно. Избегать частичного импорта; применять транзакцию для БД и безопасную очистку вновь скопированных файлов при ошибке.
9. **Не выполнять импорт на production.** Допустимо проверить на отдельной тестовой/staging среде только после проверки конфигурации и разрешения на запись в неё; не подменять это разрешением на production.

## 4. Тесты и проверки

- Filament resource: CRUD категорий и публикаций, валидность/уникальность slug, ручное редактирование slug, права/ограничения удаления, сохранение draft, проверка публикации, реакция на неактивную категорию.
- RichEditor: сохранение и повторное открытие форматирования и inline-ссылок; sanitizer сохраняет разрешённый контент и удаляет XSS; проверка совместимости с frontend HTML-контрактом.
- Импорт: все семь статей, точные даты/slug/SEO, корректный порядок, ссылки и текст; категория и обложка каждой; `5_new.png`; dry-run; повторный запуск без дублей; конфликт и отсутствие изображения; сохранение редакторских правок.
- API regression: опубликованные записи видны, скрытые нет; публичные URL изображений работают; нет приватных путей.
- Тесты `RefreshDatabase` — **только Docker и `potsandplanters_test`**. Запустить соответствующий backend suite, Pint для затронутых файлов, `git diff --check`. Указать, что реально запускалось.
- Если возможно, вручную проверить форму Filament и редактор в браузере; если нет — явно отметить отсутствие browser smoke.

## 5. Границы этапа

- **Не** менять Next.js, маршруты `/news`, CSS, metadata и sitemap.
- **Не** реализовывать News live preview статьи в Filament: он относится к BE-05.4. Google Search Preview обязателен уже сейчас.
- Не вводить автоматические редиректы при изменении slug.
- Не делать production-миграции, production-import и деплой без отдельного разрешения.
- Не заменять реальные данные mock fallback при будущей интеграции.
- Не менять утверждённый стек и архитектуру без доказанной необходимости.

## 6. Критерии приёмки

1. Категории и новости управляются через Filament 5; Google Search Preview переиспользован.
2. RichEditor сохраняет и открывает безопасный HTML без потери поддерживаемого форматирования.
3. Есть воспроизводимый, проверяемый и идемпотентный импорт семи статей и оригинальных изображений; нет необходимости набирать их вручную.
4. Проверены все семь записей, сохранены даты, slug, ссылки, тексты, SEO и обложки; сохранён порядок №6/№7.
5. API BE-05.2 продолжает работать, тесты проходят в разрешённой изолированной среде.
6. Изменения ограничены backend/импортом; production не затронут.
