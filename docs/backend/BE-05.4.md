# BE-05.4 — News: Next.js API Integration и Filament Live Preview

**Проект:** Pots & Planters 2.0  
**Статус:** ТЗ для Codex; реализация не начата  
**Область:** Next.js 16 / React 19 / TypeScript / Mantine 9, Laravel 13 / Filament 5.  
**Зависимости:** BE-05.2 и BE-05.3 реализованы и протестированы по отчётам Codex; пользователь вручную проверил работу Filament. Импорт 7 статей подтверждён в изолированном тесте, но не считать автоматически выполненным на staging/production.

## Цель

Перевести публичный News с runtime mock на реальные опубликованные записи Laravel API, сохранив внешний вид и поведение `/news` и `/news/[slug]`, обеспечить появление новых slug **без пересборки Next.js**. Добавить удобный live preview статьи в Filament, не дублируя существующий Google Search Preview.

## 1. Next.js — интеграция публичного News API

- Перевести репозиторий News на **серверные** `GET /api/v1/news` и `GET /api/v1/news/{slug}` через существующий `serverApiFetch` и `API_INTERNAL_URL`, по проверенному паттерну BE-04. Не выполнять fetch через публичный URL backend из браузера без необходимости.
- Использовать типизированный контракт и явную проверку API-ответа; сопоставить поля DTO с текущими компонентами. Не изменять backend DTO без обоснованной необходимости; если требуется — ограниченная согласованная правка с тестом.
- `news.mock.ts` оставить только для тестовых fixtures/миграционной истории, если нужно; **исключить любые runtime-импорты** из публичных страниц и production repository. Никакого fallback на mock при HTTP-ошибках, timeout, некорректном JSON или недоступном API.
- Список показывает только опубликованные новости в порядке API. Сохранить отображение карточек, дат, категорий, обложек, CTA и существующие CSS. Для пустого успешного списка предусмотреть честное пустое состояние в текущем стиле.
- Ошибки API не маскировать как пустой список или 404. 404 применять к неизвестной/неопубликованной статье **только при достоверном 404 API**; сетевые/5xx ошибки должны проходить в предусмотренную Next.js error boundary/явную ошибку.
- Не вводить дополнительный client-side state/cache без необходимости; использовать `no-store` либо эквивалентную runtime-стратегию, исключающую необходимость пересборки для новой статьи и устаревание после публикации.

## 2. Динамические страницы, SEO и совместимость

- Сохранить `/news` и `/news/[slug]`. Убрать конфликтующее `dynamicParams = false`; не ограничивать новые slug только `generateStaticParams` или build-time mock.
- Для страницы статьи и `generateMetadata` получать данные из одного server API-контракта; по возможности использовать memoization в рамках одного запроса, чтобы не плодить обращения и не получать разные версии данных. Не создавать отдельную SEO-базу.
- Сохранить `title`, `description`, canonical `https://potsandplanters.ae/news/{slug}`, Open Graph, Twitter metadata и JSON-LD `NewsArticle` с корректными URL изображений. Не выводить `dateModified` из внутренних `updated_at` без отдельного решения; дата публикации — календарная дата без выдуманного времени.
- Для архива `/news` сохранить существующее SEO из `/api/v1/page-seo/news`; не подменять его SEO отдельных статей.
- Сохранить существующие хлебные крошки, внешние ссылки, CTA и публичный дизайн. Внутренние storage paths и `API_INTERNAL_URL` не должны попадать в HTML/metadata/JSON-LD.
- Sitemap **не входит** в BE-05.4; не добавлять новые redirects при изменении slug. Исторические slug должны продолжать открываться, если записи существуют и опубликованы.

## 3. Безопасное SSR-отображение RichEditor HTML

- Вместо прежнего mock block renderer отображать `body` как очищенный HTML, пришедший из Laravel API, сохранив типографику статьи. Не использовать клиентский парсер/необязательную библиотеку, если существующие средства достаточны.
- Проверить соответствие Filament RichEditor ↔ Symfony HtmlSanitizer ↔ React SSR: абзацы, заголовки, списки, bold/italic и inline-ссылки; корректное отображение семи исторических публикаций.
- Не считать `dangerouslySetInnerHTML` самостоятельной защитой: доверенная граница — серверный sanitizer, действующий при сохранении и перед API. При необходимости добавить ограниченный defensive layer, не допускающий разного SSR/client HTML; не делать regex-санитайзер.
- Проверить `javascript:`/опасные URL, обработчики событий, `script`, `iframe`, инъекции через ссылки; `target`/`rel` должны оставаться безопасными. Не ломать разрешённое форматирование.
- Не переписывать исторический текст и не придумывать подписи или факты.

## 4. Filament — News Live Preview

- В `NewsArticleResource` добавить **отдельный от Google Search Preview** предпросмотр статьи: title, дата, категория, cover, excerpt (если выводится на публичной странице), HTML body и ссылки.
- Использовать фактический Livewire/Filament 5 state и существующий дизайн админ-панели. Preview должен обновляться по изменениям формы **до сохранения**, включая RichEditor и основные поля; если требуется debounce, выбрать разумный режим без тяжёлых запросов.
- Отображать HTML в preview безопасно: применять тот же `NewsHtmlSanitizer` на сервере к несохранённому состоянию, не выводить произвольный raw HTML из формы. Проверить работу с незавершённым draft и пустыми полями.
- Preview — приближение к публичной статье, не обещать пиксельную идентичность Next.js. Не внедрять iframe/отдельный preview API, публичный доступ к draft или сложную cross-app синхронизацию без необходимости.
- Переиспользовать существующий `SeoSearchPreview` **без копирования или изменения его контракта**. При необходимости создать компактный переиспользуемый `NewsArticlePreview`/Blade view, не строить общий UI framework.
- Не изменять правила публикации, импортёр и модели без подтверждённой необходимости.

## 6. Границы этапа

- Не менять утверждённый стек, публичный дизайн, маршруты, тексты или исторические SEO без отдельного согласования.

- Не внедрять gated preview draft через публичный API; не открывать неопубликованные материалы посторонним.
- Не переписывать BE-05.2/05.3 без причины; сохранять ручные изменения и действующие тесты.
- Не выполнять production-миграции, production-import и деплой без явного разрешения.

## 7. Критерии приёмки

1. `/news` и `/news/[slug]` используют только реальный API; runtime mock-зависимостей нет, ошибки не маскируются.
2. Новая опубликованная статья доступна по slug **без пересборки**; draft/archived и неизвестный slug дают корректный 404.
3. Публичный дизайн, сортировка, ссылки, исторический контент, SEO и JSON-LD сохранены.
4. RichEditor HTML отображается безопасно, без потери разрешённого форматирования.
5. В Filament работает live preview несохранённой статьи; Google Search Preview остаётся отдельным общим компонентом.
6. Успешные, ошибочные и граничные сценарии покрыты проверками; production не затронут.
