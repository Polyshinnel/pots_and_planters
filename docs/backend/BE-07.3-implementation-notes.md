# BE-07.3 — Filament: implementation notes

**Status:** реализовано и проверено; ожидает приёмки владельца. BE-07.4 не начат.

## Реализация

- Добавлен Filament `EnquiryResource`: новые заявки сверху, фильтры по типу/статусу/датам, поиск по имени и email, список уведомлений, read-only карточка с контактами, исходными полями, подтверждённым snapshot каталога, item snapshots и диагностикой outbox/deliveries. Создание и удаление заявок из ресурса недоступны.
- Добавлены операции `EnquiryWorkflow` для смены статуса и внутренних заметок. Добавлена append-only по интерфейсу таблица `enquiry_activities` с автором, timestamp и старым/новым статусом или заметкой.
- Добавлена отдельная Filament страница Telegram Settings: переключатели уведомлений и Squid HTTP proxy, hostname/port/username, masked secret inputs с сохранением прежних значений при пустом вводе, признаки настроенных секретов и repeater нескольких получателей. Chat ID передаётся как строка; signed BIGINT диапазон дополнительно проверяет существующая модель.
- Удаление получателя через форму — soft delete. История доставки продолжает опираться на snapshots имени/chat ID; схема FK существующих deliveries не менялась. Пустой список активных получателей показывается как диагностическое состояние.
- Панель Filament уже ограничена `User::canAccessPanel()` по `is_admin`; страница настроек дополнительно реализует `canAccess()`.

## Схема и совместимость

BE-07.2 уже содержит текущий статус заявки, encrypted casts секретов, менеджер настроек, signed/unique chat IDs, soft deletes и snapshots доставок. Единственное необходимое расширение — таблица `enquiry_activities`; существующие таблицы и `POST /api/v1/enquiries` не менялись.

В workspace до начала BE-07.3 присутствовали многочисленные незакоммиченные BE-07.2 файлы (API, models, services, migration, tests и notes). Они сохранены; их наличие видно в итоговом `git status` и они не переписывались в рамках интерфейса, кроме добавления связи `Enquiry::activities()`.
