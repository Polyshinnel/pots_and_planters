# BE-07 — Enquiries & Telegram Integration

**Проект:** Pots & Planters 2.0  
**Статус:** ТЗ подготовлено; реализация не начата и не проверена.  
**Основание:** PROJECT_CONTEXT.md и ROADMAP.md, срез 22.10.2026.

## 1. Цель

Создать надёжный сквозной процесс обработки четырёх типов заявок: `contact`, `product_enquiry`, `catalogue_download`, `cart_enquiry`. Обеспечить первичное сохранение в MariaDB, управление заявками в Filament 5, единый `POST /api/v1/enquiries`, асинхронные уведомления Telegram через Redis/Horizon и выдачу приватного PDF только после успешного сохранения заявки. Подключить существующие формы Next.js без изменения утверждённого публичного дизайна.

## 2. Обязательные ограничения

- Стек: Next.js 16, React 19, TypeScript, Mantine 9; Laravel 13, PHP 8.4, Filament 5; MariaDB, Redis, Horizon.
- Реализовывать вертикально: БД → Laravel → Filament → API → Next.js → тестирование.
- Не выполнять production migration, import или deploy без отдельного разрешения.
- Сохранять существующие маршруты, SEO, публичный дизайн, тексты и UX, кроме явно необходимых изменений поведения отправки.
- Не подменять ошибки API mock-данными или фиктивным успехом.
- Не придумывать товары, цены, SKU, контакты и данные пользователей.
- Корзина остаётся в localStorage; при неуспешной отправке не очищать её и не удалять недоступные позиции молча.
- PDF каталогов хранятся приватно; нельзя раскрывать storage path, внутренний URL или публичную постоянную ссылку на файл.
- Перед приёмом реальных персональных данных проверить актуальность `/private-policy` и согласовать необходимые изменения отдельно.
- Изучить существующие тесты, DTO, серверные API-клиенты, формы, модальные окна, Filament-паттерны и ручные изменения до правок. Не проводить посторонний рефакторинг.

## 4. Этап BE-07.2 — MariaDB, Laravel и API

**Цель:** надёжно принимать и сохранять заявки независимо от Telegram.

**Действия:**
1. После аудита создать миграции и модель заявок. Предусмотреть UUID/публичный непрогнозируемый идентификатор, тип, статус, контактные данные, согласованные серверные snapshots, технические метаданные и timestamps. Не хранить лишние PII и секреты.
2. Зафиксировать допустимые поля для каждого типа. Клиентские наименования, цены, ссылки на PDF и другие значимые сведения не считать доверенными: проверять идентификаторы и строить snapshot из БД. Для BE-08-зависимых товаров предусмотреть явно документированное совместимое поведение без вымышленных данных.
3. Реализовать `POST /api/v1/enquiries` с FormRequest/валидацией, типизированным ответом, корректными кодами 201, 422, 404/409, 429 и 5xx по принятому в репозитории API envelope.
4. Добавить idempotency key и атомарную защиту от повторного создания при двойном клике, сетевом повторе и конкурентных запросах. Повтор с тем же ключом и тем же содержимым возвращает тот же результат; конфликтующий payload отклоняется. Продумать TTL/retention ключей и уникальные ограничения.
5. Сохранять заявку и задачу на уведомление согласованно. Исключить ситуацию, когда заявка зафиксирована, а задача уведомления безвозвратно потеряна: выбрать и обосновать транзакционный outbox или другой доказуемо надёжный механизм с восстановлением.
6. Добавить разумные ограничения размера payload, rate limiting и антиспам без блокировки обычных пользователей; не логировать целиком тела запросов и PII.
7. Секреты Telegram и внутренние токены — только конфигурация окружения, без передачи в API/логи.

**Приёмка:** успешная запись существует в MariaDB до ответа об успехе; ошибки валидации не создают заявок; повторные и конкурентные запросы не создают дублей; ошибка очереди/Telegram не теряет заявку; unit/feature tests покрывают сценарии.

## 5. Этап BE-07.3 — Filament 5

**Цель:** сделать заявки удобными для обработки менеджерами.

**Действия:**
1. Реализовать список и read-only detail с фильтрами по типу, статусу, датам и поиском по безопасным полям.
2. Предусмотреть изменение статуса, историю действий, временные отметки и при необходимости внутреннюю заметку; точные статусы согласовать с существующей моделью и UX.
3. Показать проверенный snapshot и состав корзины, не доверяя будущим изменениям товарного каталога.
4. Отдельно отображать состояние доставки Telegram и ошибку последней попытки без раскрытия секретов; предусмотреть контролируемый ручной повтор, если это соответствует текущей инфраструктуре.
5. Применить права доступа Filament, защиту PII, безопасный вывод пользовательского текста (без исполнения HTML), ограничение экспорта/массовых операций.
6. Повторно использовать существующие паттерны UI Filament; не строить новый универсальный framework.

**Приёмка:** заявки доступны уполномоченному менеджеру; статусы и история сохраняются; пользовательские данные безопасно отображаются; неавторизованный доступ исключён; тесты проходят.

## 6. Этап BE-07.4 — Telegram, Horizon и gated PDF

**Цель:** уведомлять менеджеров без риска потери заявок и защищённо отдавать каталоги.

**Действия:**
1. Реализовать очередь уведомлений в Redis/Horizon, контролируемые retry/backoff, таймауты, журнал попыток, состояние доставки и диагностику failed jobs.
2. Сформировать безопасный формат сообщения Telegram: тип заявки, идентификатор, нужные контактные сведения и snapshot. Экранировать пользовательский текст, ограничивать длину, не выводить токены и лишние PII.
3. Исключить параллельную отправку одного и того же pending-уведомления, насколько позволяет архитектура. Документировать, что внешнее Telegram API не гарантирует end-to-end exactly-once; реализовать локальную дедупликацию и безопасную повторную обработку.
4. Для `catalogue_download` после успешного сохранения заявки выдавать короткоживущий одноразовый или иным образом контролируемый download grant, привязанный к конкретной заявке и каталогу.
5. PDF отдавать только через авторизованный Laravel download endpoint/контролируемую временную ссылку, с проверкой гранта, наличия файла и опубликованности/допустимости каталога согласно согласованной политике. Не раскрывать приватные storage path. Учитывать повтор запроса после потери сетевого ответа и idempotency.
6. При ошибке сохранения заявки PDF не отдавать. При сбое Telegram после сохранения доступ к PDF не блокировать, если бизнес-условие выполнено.

**Приёмка:** Telegram недоступен → заявка сохранена, уведомление подлежит повтору; восстановление очереди работает; повторная обработка не создаёт новую заявку; приватный PDF нельзя получить без корректного grant; истёкшие/поддельные grants отклоняются; успешный download проверен.

## 7. Этап BE-07.5 — Next.js и сквозная проверка

**Цель:** подключить четыре существующих пользовательских сценария к реальному API.

**Действия:**
1. Использовать существующие формы, modal, API client и TypeScript DTO; согласовать browser → Next.js → Laravel маршрут с текущими security/CORS правилами.
2. Передавать idempotency key на одну логическую отправку; не генерировать новый ключ при автоматическом retry того же payload.
3. Для всех четырёх типов обеспечить клиентскую и серверную валидацию, pending state, защиту от двойного клика, реальные сообщения success/error и доступность с клавиатуры.
4. Для catalogue download запускать скачивание только после подтверждённого сохранения и выдачи grant; обработать ошибки получения PDF отдельно от ошибок создания заявки.
5. Для cart enquiry сохранять localStorage при ошибке. Политику очистки после подтверждённого успеха зафиксировать по текущему UX; не терять позиции без уведомления.
6. Не менять SEO, canonical, страницы каталога и `/catalogues?category=<slug>`; не возвращать runtime mock fallback.
7. Добавить frontend tests и Laravel tests на все типы, ошибки, повтор, гонки, сбой Telegram, отказ в скачивании, 503 и недоступные сущности.
8. Выполнить существующие regression suites, typecheck, Laravel suite, Pint затронутых файлов, production build (`NODE_ENV=production`), `git diff --check`; провести staging/API/SSR и при возможности browser smoke четырёх форм и Filament. Не проводить production операции.

**Приёмка:** все четыре сценария проходят end-to-end на тестовых данных; ошибочный API не маскируется; PDF не скачивается до успешной заявки; корзина сохраняется при сбое; отсутствуют регрессии BE-02…BE-06.
