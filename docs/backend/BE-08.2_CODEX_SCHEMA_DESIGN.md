# BE-08.2 — Read-only проектирование Product Schema и API Contracts

**Проект:** Pots & Planters 2.0  
**Статус:** ТЗ для Codex; только проектирование, без реализации.  
**Основной источник решений:** `BE-08_ARCHITECTURE_DECISIONS.md`.  
**Контекст:** `PROJECT_CONTEXT.md`, `ROADMAP.md`, результаты BE-08.1C A/B/C.  

## Цель

На основании утверждённого ADR и **фактического текущего репозитория** подготовить проверяемый проект схемы MariaDB, моделей Laravel, интерфейсов Filament, публичных API `/api/v1` и контрактов Next.js для модуля Products. Не писать код и не выполнять миграции до отдельного утверждения.

## Ограничения

- **Read-only**: не изменять файлы репозитория, БД, миграции, документацию и конфигурацию. Не выполнять импорт SQL, не запускать команды с записью. Не трогать production.
- Не предполагать, что репозиторий совпадает с историей обсуждения. Начать с `git status --short` и адресного аудита фактических моделей, миграций, API, Filament, Next.js, корзины, SEO и enquiries. Не затрагивать существующие пользовательские изменения.
- Следовать ADR; при противоречии между ADR, PROJECT_CONTEXT/ROADMAP и кодом **явно сообщить**, а не молча выбирать вариант.
- Стек неизменен: Laravel 13, Filament 5, MariaDB, Next.js 16, React 19, TypeScript, Mantine 9. Один язык English, одна валюта AED.
- Не вводить ProductVariant. Каждый продаваемый размер/цвет/finish — отдельный Product. Не создавать публичную страницу Series.
- Не менять публичный дизайн и маршруты. Не вводить runtime mock fallback. Повторно использовать Google Search Preview.
- Не придумывать данные OpenCart, SKU, цены, характеристики и правила налогообложения.

## A. Read-only сверка репозитория

1. Найти и описать существующие Category и Category API, публичные идентификаторы, slug, SEO, redirects и связи с PDF-каталогами.
2. Проверить Filament resources, SEO preview, image upload patterns и политики доступа.
3. Проверить текущие Product types/fixtures, каталожные страницы, фильтры, карточки, product gallery, canonical, sitemap, JSON-LD, legacy redirects.
4. Проверить корзину/localStorage и `enquiry_items`, backend validation, feature flags, Telegram snapshots.
5. Зафиксировать точные пути файлов и точки интеграции. Сопоставить с ADR; не вносить исправления.

## B. Схема MariaDB и Eloquent (проект, не миграции)

Подготовить ERD и таблицу сущностей с полями, типами, nullable, FK, unique/indexes, правилами удаления и публикации. Обязательно рассмотреть:

- `products`: стабильная идентичность (internal/public), Brand, Supplier, Product Type, optional Series, SKU, Name, price AED, публикация, primary Category, slug, SEO, OG image, legacy identity.
- `brands`, `suppliers`, `product_series` и правила активности/видимости; Series принадлежит Brand.
- `product_types`, `attributes`, связи type↔attribute, опции select/multiselect, значения характеристик товаров и их типизация; управляемость через Filament без изменения кода.
- `product_category` many-to-many и инвариант primary Category ∈ назначенных категорий.
- `category_filter_config`: индивидуальные видимость, порядок и тип фильтра для Category; выборка по всем товарам категории, не только primary.
- Product media: упорядоченная галерея, ровно одно главное при наличии изображений, alt per product, автоматическое/ручное значение; безопасное переиспользование физического файла.
- История slug/primary-category redirects и legacy mapping, не смешивая новые redirect rules с BE-09 OpenCart import.
- Цены decimal без float; отсутствие цены ≠ 0. Без фиктивного stock/fast delivery.

Особо описать **двухуровневую защиту уникальности `(brand_id, sku)`**: Filament/Laravel validation + MariaDB UNIQUE, регистр/пробелы, конкурентные запросы, смена Brand/SKU и импорт. Не выбирать молча политику нормализации — показать варианты и рекомендацию.

Показать, как избежать сложного универсального EAV-фреймворка, сохранив фильтрацию и корректную валидацию динамических атрибутов. Привести 2–3 альтернативы хранения и обоснованную рекомендацию с последствиями для SQL-запросов/индексов.

## C. API-контракты и frontend integration (проект)

1. Предложить точные endpoints `/api/v1` для product list by category, detail by canonical identity, series siblings, filter definitions/facets и при необходимости brands/suppliers; показать DTO в JSON-примерах с **условными, явно обозначенными данными**.
2. Описать pagination, sorting AED price, filter query parameters, empty/error states, `no-store`, публикацию и effective visibility при отключённом Supplier.
3. Описать один canonical URL `/shop/{primaryCategorySlug}/{productSlug}`, ссылки из любых категорий и 301 с неосновных URL; учесть существующие `/product/{slug}` и legacy routes.
4. SEO: title, meta description, OG image, slug; fallback и ручные overrides; JSON-LD из реальных данных, без ложного stock availability.
5. Series: cross-category siblings перед рекомендациями, без отдельного series route; отдельно отметить нерешённые limit/order.
6. Описать совместимость Next.js catalog/product/cart с существующими компонентами и отсутствие mock fallback.
7. Определить необходимый минимальный snapshot для Product/Cart Enquiry и переход с SKU-identity на стабильный Product ID, но **не включать** эти формы на этом этапе.
