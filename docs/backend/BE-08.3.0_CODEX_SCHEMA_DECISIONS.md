## 3. Обязательные решения для разбора

### D1. SKU и уникальность Brand + SKU

- Инвариант: SKU обязателен у нового Product; уникальна пара `(brand_id, sku)`; одинаковый SKU у разных брендов допустим; отсутствующие legacy SKU не выдумывать.
- Сравнить: (a) хранить канонизированный SKU, (b) сохранять оригинал + отдельный normalized key, (c) точное сравнение. Рекомендовать вариант, явно описав trim, регистр, Unicode/ASCII, внутренние пробелы, пунктуацию, MariaDB collation, DB UNIQUE и конкурентные записи.
- Не менять legacy SKU без явного решения; привести реальные примеры **только из доступного аудита/данных**, не придумывать статистику. Указать, как выявлять коллизии при смене Brand/SKU и импорте.

### D2. Точность цены AED

- Инвариант: одна валюта AED, цена Product nullable; `NULL` означает `Price on enquiry`; `0` не означает бесплатный товар; положительные цены OpenCart подтверждены владельцем.
- Сопоставить `DECIMAL(15,2)` и `DECIMAL(15,4)` с реальной точностью/максимумом значений экспорта **если исходные данные доступны**. Если недоступны — прямо отметить, что нельзя подтвердить source scale, и рекомендовать безопасную предварительную схему.
- Разделить хранение, API decimal string и UI форматирование; не вводить налоговые предположения.

### D3. Хранение динамических характеристик

- Инвариант: Product Types и Attributes управляются из Filament; типы `text`, `number`, `select`, `multiselect`, `boolean`; применимость/required/order/filterable задаются для Product Type; значения нельзя терять при редактировании справочников.
- Сравнить JSON, отдельные scalar-таблицы и `product_attribute_values` + `product_attribute_selections` (предложение BE-08.2). Оценить FK, CHECK, индексы, фильтры, число запросов, сложность Filament, миграцию legacy.
- Для размеров указать числовые Attribute с единицей измерения, различие Color/Finish; не придумывать обязательные для всех Product поля.

### D4. Slug и история URL

- Инвариант: `/shop/{primary-category-slug}/{product-slug}`, одна Primary Category и один canonical Product URL; secondary-category links ведут на canonical; старые пути не отдаются другим товарам; прямые 301 без цепочек.
- Сравнить глобально уникальный `products.slug` и уникальность в рамках категории, учитывая существующий `/product/{slug}`. Описать `product_url_paths` (canonical/history/compatibility), ограничения уникальности и безопасную смену slug/Primary Category.
- Зафиксировать техническое несоответствие: Next.js `permanentRedirect` в проверенном baseline выдаёт 308, а требование — 301; предложить способ решения, **не реализовывать**.
- Миграция OpenCart `?product_id` и aliases — BE-09, не выдумывать mappings.

### D5. Общий MediaAsset

- Инвариант: несколько изображений Product, независимый порядок и main image; только одно главное; первое загруженное становится главным; ALT auto/manual на уровне связи Product–Image; OG по умолчанию main, с override.
- Сравнить прямые file paths и `media_assets` + `product_images`; описать безопасное переиспользование файлов между Product, дедупликацию, `RESTRICT`/очистку и физическое удаление после commit.
- Не вводить новую библиотеку или внешнюю зависимость без обоснования.

### D6. Физическое хранилище

- Сверить реально настроенные Laravel disks и существующие практики News/Category/Catalogue. Предложить минимально совместимое решение для dev, с возможностью object storage в будущем через `disk/path`, без миграции всех существующих медиа.
- Не принимать решения о S3/production storage и не выполнять перенос файлов. Отдельно перечислить остающиеся вопросы: допустимые форматы, лимиты, image conversions.
