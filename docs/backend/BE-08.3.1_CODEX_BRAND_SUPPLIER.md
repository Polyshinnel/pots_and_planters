## Часть A — закрепить утверждённые решения BE-08.3.0

В `docs/backend/BE-08_ARCHITECTURE_DECISIONS.md` внести компактный раздел **«D1–D6 — утверждено владельцем 2026-11-02»** и скорректировать устаревшие пометки «не согласовано» только в части D1–D6. Не переписывать прочие договорённости. Зафиксировать:

- **D1 SKU:** обязательный для нового Product; trim внешних пробелов, ASCII `a-z` → `A-Z`; внутренние пробелы/пунктуация сохраняются; без дополнительного ASCII-only whitelist и без дополнительных проверок перед утверждением; MariaDB `UNIQUE(brand_id, sku)` с явно определённой collation и единая нормализация в будущих Filament/API/импорте. Отсутствующие legacy SKU не генерировать.
- **D2 Price:** `DECIMAL(15,4) NULL`, AED; только положительная цена или NULL (`Price on enquiry`); API decimal string, без float; VAT не предполагать.
- **D3 Attributes:** typed scalar values (`text`, `number`, `boolean`) + отдельные selections для select/multiselect, с ограничениями целостности и запретом разрушительных изменений заполненного Attribute без явной миграции.
- **D4 URL:** глобально уникальный Product slug, уникальный реестр canonical/history/compatibility full paths; один canonical, старые пути резервируются, прямые HTTP 301 до SSR streaming; OpenCart aliases/`?product_id` — BE-09.
- **D5 Media:** `media_assets` + `product_images`, общий физический файл, ALT/order/main в контексте Product, безопасное удаление только после commit и проверки ссылок; точный механизм main-инварианта спроектировать в соответствующем будущем этапе.
- **D6 Storage:** `disk/path`, для локального dev Product images используют существующий `public` disk; production storage, форматы, лимиты и conversions пока не утверждены.

**Граница:** утверждение D1–D6 НЕ разрешает сейчас создавать Product, Price, Attribute, Media или URL таблицы. Не заявлять, что вся схема BE-08.2 окончательно утверждена; остальные открытые вопросы сохраняются.

**Проверка части A:** diff ADR точно отражает шесть решений; не изменены независимые архитектурные ограничения; нет прежних взаимоисключающих формулировок D1–D6.

## Часть B — минимальная реализация Brand и Supplier

### Цель

Два независимых справочника Laravel/Filament, готовых к будущим FK Product, без создания Product и без изменения публичного сайта.

### Разрешённые изменения

1. **MariaDB migrations (новые, не редактировать применённые):**
   - `brands`: внутренний `id` по проектной конвенции, уникальный неизменяемый `public_id` UUID, `name` (обязательное), `is_active` boolean default true, timestamps.
   - `suppliers`: тот же минимальный набор полей.
   - Добавить необходимые индексы/ограничения согласно существующему проекту; **не вводить неутверждённые slug, адреса, реквизиты, логотипы, контакты или новые бизнес-поля**.
   - Не создавать `products`, product FK, seeders с фиктивными брендами/поставщиками.
2. **Eloquent:** `Brand` и `Supplier`, корректные casts, генерация `public_id` по существующей конвенции, защита неизменности публичного ID. Не добавлять искусственные product relationships до появления модели Product.
3. **Filament 5:** отдельные ресурсы Brand и Supplier в существующей admin-only панели. Список: name, active, timestamps (если соответствует текущим паттернам), поиск по name, сортировка, фильтр active. Форма: name и active, понятные English labels/errors. Создание, редактирование, просмотр/архивирование — по существующим паттернам проекта. Не вводить новую систему ролей, UI-framework или сторонние пакеты.
4. **Удаление/активность:** `is_active=false` — не удаление записи. Не реализовывать пока product visibility, поскольку Product отсутствует. Для будущих связанных записей проектировать `RESTRICT`/запрет удаления, но не создавать фиктивные связи; если нужна защита от удаления уже сейчас — выбрать простую совместимую политику и задокументировать. Не обещать работу Supplier toggle с товарами до BE-08.4/08.5.
5. **Validation:** trim имени; не создавать пустые/whitespace-only имена; ограничения длины совпадают с БД. **Уникальность имён не является утверждённым бизнес-инвариантом**: не добавлять DB UNIQUE(name) без отдельного обоснования/согласования. `public_id` не редактируется в UI.

### Тесты и приёмка

- Проверить миграции в **разрешённой локальной/dev/test БД**, не в production/staging. Не запускать destructive `migrate:fresh` на общей/неподтверждённой БД.
- Feature/unit tests: создание двух справочников, обязательность/trim имени, default active, переключение active без удаления, UUID uniqueness/immutability, admin access, отсутствие доступа не-администратора, редактирование через Filament, корректная фильтрация/поиск. Применить принятые в репозитории механизмы тестирования Filament, не придумывать несуществующие helpers.
- Проверить, что существующие Category/Catalogue/News/Contacts/Enquiry маршруты и тесты не сломаны; выполнить релевантный backend suite, Pint и `git diff --check`.
- Тесты Laravel запускать только по правилам `AGENTS.md`, через Compose и `potsandplanters_test` там, где это предписано; не запускать тесты против рабочей dev БД с данными.
- Не изменять frontend и публичные маршруты; frontend build не обязателен при отсутствии изменений frontend.
- Убедиться, что отключение Supplier пока **только меняет поле справочника**, а не влияет на несуществующие товары.
