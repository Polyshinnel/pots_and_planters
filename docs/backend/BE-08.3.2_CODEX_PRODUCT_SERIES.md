# BE-08.3.2 — Product Series: справочник Laravel / Filament

**Проект:** Pots & Planters 2.0  
**Тип:** небольшая реализационная задача для Codex  
**Статус:** разрешена реализация только в пределах этого ТЗ; не считать принятой до отчёта и проверки.  
**Язык:** ТЗ и отчёт — русский; UI-лейблы Filament — English.

## 1. Цель

Создать самостоятельный справочник **Product Series**, относящийся к одному **Brand**. В будущем один Product сможет необязательно принадлежать одной серии; серия сможет объединять товары из разных Category. На этом этапе модели Product и связи с товарами ещё нет.

Основание: `docs/backend/BE-08_ARCHITECTURE_DECISIONS.md`, ADR-04; ранее принятый BE-08.3.1 Brand + Supplier. Отдельной публичной страницы серии не будет.

## 3. Согласованная модель и границы

- Сущность: `ProductSeries`, таблица `product_series` **или** другое имя, если оно уже однозначно закреплено в актуальном проектном ERD; выбрать согласованное имя и использовать везде последовательно. В BE-08.2 предложено `product_series`.
- Минимальные поля: внутренний `id`; уникальный, неизменяемый `public_id` UUID; `brand_id` как обязательный FK на `brands.id`; обязательный `name` до 255 символов; `is_active` boolean default true; timestamps.
- **Не добавлять без согласования** slug, SEO, описание, обложку, позицию сортировки, отдельный URL, публичную API-схему или тестовые бизнес-данные.
- `name` не обязан быть глобально уникальным. **Рекомендован инвариант:** уникальное имя внутри Brand не вводить без отдельного утверждения; допускаются совпадающие названия. Для отображения серии в Filament показывать связанный Brand.
- FK `brand_id`: использовать совместимую с проектом стратегию `RESTRICT`/`NO ACTION` при удалении Brand; каскадное удаление серий запрещено.
- `is_active=false` архивирует серию, но не удаляет её; не придумывать сейчас поведение существующих Product (их ещё нет).
- Никаких связей с Category: разные категории будут объединяться через Product позднее.
- **Бренд серии должен оставаться согласован с брендом Product** в будущем Product Core. Пока реализовать только обязательную принадлежность серии Brand, не создавать Product FK или искусственную связь.

## 4. Реализация

### 4.1 MariaDB

- Добавить **новую** миграцию справочника с FK, индексом `brand_id`, уникальным `public_id`, обязательными полями и timestamps.
- Соблюдать принятые конвенции и MariaDB-совместимые типы; не редактировать уже применённые миграции BE-08.3.1.
- Миграцию выполнять только в подтверждённой локальной test/dev БД согласно `AGENTS.md`. Не запускать `migrate:fresh` на общей/рабочей БД.

### 4.2 Eloquent

- `ProductSeries` с `belongsTo(Brand::class)`, корректными casts, генерацией и защитой неизменности `public_id` по образцу Brand/Supplier.
- При необходимости добавить `Brand::productSeries()` как обычную обратную связь. Не добавлять `products()` до появления Product.
- Валидация: `brand_id` должен ссылаться на существующий Brand; имя trim + nonempty + длина 255; активность — boolean.
- Для **создания** серии в Filament предлагать только активные Brand, если это согласуется с существующим UI; для **редактирования** уже связанный неактивный Brand должен оставаться видимым и выбранным, чтобы форма не теряла значение. Если текущие конвенции требуют другого решения, явно описать его в отчёте. Не перепривязывать серию автоматически при отключении Brand.

### 4.3 Filament 5

- Создать отдельный Product Series resource в существующей admin-only панели с обычными страницами List/Create/Edit.
- Форма: `Brand` (обязательный select с поиском), `Name`, `Active`. Подписи на английском. `public_id` не редактируется.
- Список: `Name`, `Brand`, `Active`, created/updated timestamps по существующему паттерну; поиск по имени серии, фильтр по Brand и Active, сортировка.
- Запретить физическое удаление через Filament (архивирование через Active), как в Brand/Supplier. Не менять навигацию других ресурсов и не вводить общий UI framework.
- Доступ — только существующие администраторы, без новой системы ролей.

## 5. Тесты и критерии приёмки

Минимум проверить автоматизированно:

1. Создание серии с существующим Brand, UUID, default active, timestamps и FK.
2. Trim имени, отклонение пустого/whitespace-only имени, отсутствие Brand и несуществующий Brand.
3. Редактирование имени/Brand/Active, UUID не меняется; отключение серии не удаляет её.
4. Запрет удаления Brand, на который ссылается серия (через DB FK); без cascade.
5. Filament CRUD: только admin; non-admin не получает доступ; поиск и фильтры по Brand/Active.
6. Существующие Brand/Supplier tests и полный backend suite не регрессировали; Pint `--test`, `git diff --check` проходят.
7. Проверить форму с **неактивным Brand**: редактирование уже существующей серии не теряет связь и не вызывает скрытой подмены.

Проверки проводить в изолированной `potsandplanters_test` через Docker Compose по правилам `AGENTS.md`, с HTTP fake там, где требуется; не использовать production/staging и не отправлять реальные сообщения Telegram. Зафиксировать точные команды и числа тестов. Если какой-то тест не проходит, указать причину, не скрывать ошибку.

## 6. Жёсткие ограничения

- **Не создавать** Product, Product Type, Attributes, options, галерею, category filters, product API, Next.js изменения или OpenCart importer.
- Не создавать public series route, SEO или блок `Other products in this series`: они относятся к будущему Product API/frontend.
- Не менять публичный дизайн, SEO и текущие маршруты, Cart/Enquiry, Telegram, существующие данные.
- Не включать Product/Cart Enquiry.
- Не выполнять production/staging миграции и деплой.
- Не менять утверждённый стек и не добавлять зависимости без необходимости.
