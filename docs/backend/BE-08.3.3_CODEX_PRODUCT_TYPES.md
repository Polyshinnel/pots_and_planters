# BE-08.3.3 — Product Types: справочник Laravel / Filament

**Проект:** Pots & Planters 2.0  
**Тип:** ограниченная реализационная задача для Codex  
**Статус:** разрешено реализовать только BE-08.3.3; приёмка после отчёта, тестов и ручной проверки.  
**Язык:** ТЗ/отчёт — русский, подписи Filament — английский.

## 1. Цель

Создать самостоятельный управляемый справочник **Product Types**, который позднее будет определять допустимые характеристики товара через отдельную связь Product Type ↔ Attributes (BE-08.3.5). В рамках текущего этапа Product Type не связан ни с товарами, ни с характеристиками, ни с Brand/Series/Category.

## 2. Read-only аудит перед изменениями

1. Прочитать применимый `AGENTS.md`, актуальный `docs/backend/BE-08_ARCHITECTURE_DECISIONS.md`, `docs/backend/BE-08.2_SCHEMA_DESIGN_REPORT.md`, а также `PROJECT_CONTEXT.md` и `ROADMAP.md`, **если они есть в репозитории**. Если отсутствуют — отметить, не создавать и не подменять их.
2. Проверить `git status --short`, текущие миграции, модели, Filament 5 resources и тесты `Brand`, `Supplier`, `ProductSeries`. Учитывать все незакоммиченные и ручные изменения, включая FIX-01.
3. Проверить, не существует ли уже `product_types` или эквивалентной сущности. При конфликте с ADR/реальным кодом остановиться и описать расхождение; не создавать дубли.
4. Сверить фактический нейминг таблиц, UUID, доступ администраторов, навигацию, формы, active-фильтры и запрет удаления. Не копировать устаревшие предположения из истории переписки.

## 3. Контракт справочника

- Таблица: `product_types` (если в актуальном репозитории не закреплено иное имя).
- Поля: внутренний `id` (совместимый с существующими FK), `public_id` UUID уникальный и неизменяемый, `name` VARCHAR(255) обязательное, `is_active` boolean default true, `created_at`, `updated_at`.
- `name`: trim внешних пробелов, отклонение пустого/whitespace-only, максимум 255 символов. **Не вводить уникальность имени** без ранее утверждённого требования; не генерировать slug из имени.
- `public_id` автоматически создаётся, не редактируется ни в модели, ни через Filament. Следовать фактическому шаблону Brand/Supplier/ProductSeries.
- `is_active=false` означает архивирование справочника; не удалять запись физически через Filament. Пока не вводить правила видимости будущих Product и не менять их статусы.
- Не добавлять `brand_id`, `category_id`, `series_id`, `slug`, SEO, описания, sort_order, media, дополнительные настройки или публичные маршруты без явного требования.
- Не создавать начальные типы товаров или fixtures, выдаваемые за реальные бизнес-данные. Тестовые factory/fixtures допустимы только внутри тестов.

## 4. Изменения

### 4.1 MariaDB

- Добавить отдельную новую миграцию `create_product_types_table` с нужными ограничениями, уникальным `public_id`, timestamps и `is_active` default true.
- Не редактировать ранее применённые миграции BE-08.3.1 и BE-08.3.2.
- Миграцию разрешено применить **только** в подтверждённой изолированной локальной dev/test БД, предпочтительно `potsandplanters_test`, через существующий Docker Compose. До запуска проверить фактическое имя БД. Запрещены production/staging, `migrate:fresh` на общей БД и любые destructive операции с рабочими данными.

### 4.2 Eloquent

- Добавить `ProductType` с table mapping, fillable/casts, генерацией и защитой UUID, валидацией имени согласно существующим паттернам.
- Не добавлять связи `products()` или `attributes()` до соответствующих этапов.
- Не строить новую общую базовую модель или универсальную CRUD-абстракцию ради одного справочника.

### 4.3 Filament 5

- Отдельный `ProductTypeResource` со страницами List/Create/Edit в существующей admin-only панели.
- Форма: `Name` (required, trim, max 255), `Active` (default true). `public_id` только для чтения при необходимости, но не редактируется.
- Таблица: `Name`, `Active`, timestamps; поиск по имени, сортировка, фильтр Active по паттерну существующих ресурсов.
- Физическое удаление через Filament отключить, включая bulk actions. Не добавлять отдельные роли или менять проверку `is_admin`.
- Навигация и подписи на английском; разместить рядом с существующими товарными справочниками, не изменяя другие разделы панели.

## 5. Проверки и критерии приёмки

Автоматически проверить:

1. Миграция создаёт корректную таблицу, уникальный UUID и active default.
2. Создание Product Type; trim имени; запрет пустого и whitespace-only имени, ограничение длины.
3. Изменение имени и активности; UUID остаётся неизменным; отключение не удаляет запись.
4. Доступ к Filament List/Create/Edit только для администраторов; non-admin не получает доступ.
5. Filament: создание, редактирование, поиск, сортировка и фильтр Active; отсутствие delete/bulk delete.
6. Повторный запуск профильных тестов Brand/Supplier/ProductSeries, затем **всего backend suite**. Сохранить отсутствие регрессий Enquiry/Telegram после FIX-01.
7. Pint `--test` по изменённым PHP-файлам и `git diff --check`. Полный Pint можно запускать диагностически: известные 11 посторонних замечаний не исправлять в этом этапе, но зафиксировать фактический результат.

Для каждого запуска записать точную команду, окружение и числа тестов/assertions. Не отправлять реальные Telegram-сообщения; использовать HTTP fake там, где тесты доставки требуют. Ручную проверку Filament проводит владелец после отчёта Codex; **не утверждать, что она пройдена, до его подтверждения**.

## 6. Жёсткие ограничения

- Не создавать `attributes`, `attribute_options`, `product_type_attribute`, `products`, category filters, медиа, URL history, OpenCart import или Product API.
- Не добавлять публичные Next.js маршруты/страницы и не менять дизайн, SEO, Cart/Enquiry или Telegram.
- Не менять Brand, Supplier, ProductSeries без подтверждённой необходимости и отдельного объяснения.
- Не изменять существующие данные и не делать production/staging миграции или deploy.
- Не добавлять зависимости и не проводить посторонний рефакторинг/массовое форматирование.
