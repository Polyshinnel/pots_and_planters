## 1. Цель

Реализовать **независимый справочник определений характеристик товара** (`attributes`) и их допустимых вариантов (`attribute_options`) в MariaDB → Laravel 13 → Filament 5, с тестами. Это определения, а не значения характеристик конкретного Product.

Поддерживаемые типы: `text`, `number`, `boolean`, `select`, `multiselect`. Варианты допустимы только для `select`/`multiselect`. Справочник должен быть пригоден для последующих BE-08.3.5 и BE-08.4.3 без преждевременного добавления связей.

## 4. Этап B — MariaDB / Eloquent

Создать миграции для двух таблиц (согласовать точные имена колонок с ADR и существующими соглашениями):

**`attributes`**:
- внутренний `id` BIGINT PK;
- `public_id` UUID, unique, генерируется автоматически, не меняется после создания;
- `name` — обязательное человекочитаемое название, trim, max 255;
- `code` — стабильный технический ключ для будущих значений и фильтров; определить строгую и понятную нормализацию (`lowercase snake_case` либо `kebab-case`) и уникальный DB индекс; **не менять автоматически при переименовании name**;
- `type` — одно из пяти утверждённых значений;
- `unit` — nullable единица измерения для числовых характеристик (например `cm`), без конвертации единиц и без автоматического назначения значений; для других типов должна быть `NULL`;
- `is_active` boolean default true;
- timestamps.

**`attribute_options`**:
- внутренний `id` BIGINT PK;
- `public_id` UUID unique и immutable;
- `attribute_id` FK на `attributes.id`, удаление родителя ограничено (`RESTRICT`);
- `label` — обязательная подпись, trim, max 255;
- `value` — стабильный технический ключ внутри Attribute, не зависящий от переименования label; `UNIQUE(attribute_id, value)`;
- `sort_order` integer default 0;
- `is_active` boolean default true;
- timestamps.

**Примечание:** `code`, `unit` и `value` — проектные предложения для проверки по ADR. Если в утверждённой схеме эти поля названы или организованы иначе, сохранить совместимость и объяснить выбор. Не вводить локализацию или SEO-поля без утверждённого требования.

Ограничения на уровне приложения и БД, насколько поддерживает MariaDB: допустимые значения `type`; корректность `unit` для `number`; уникальные ключи; FK. Для select/multiselect options должны существовать только у соответствующего Attribute; запретить добавление options к scalar type. **Изменение типа Attribute, у которого есть options, блокировать** (без автоматического удаления); в будущем при наличии Product values изменение заполненного типа также должно быть запрещено.

Создать модели `Attribute`, `AttributeOption` с отношением `hasMany`/`belongsTo`, immutable UUID, безопасным заполнением, нормализацией и понятной валидацией. Не полагаться только на Filament-валидацию: модельный/сервисный слой должен защищать базовые инварианты, а DB — уникальность и FK. Не создавать искусственные стартовые данные.

## 5. Этап C — Filament 5

Реализовать административный справочник **Attributes** в стиле уже существующих BE-08 ресурсов:

- List: name, code, type, unit (если есть), active, число options, created/updated; поиск, сортировка, фильтр type и active.
- Create/Edit: name, code, type, unit только для number, active.
- Для select/multiselect — удобное управление options (relation manager либо повторяемый редактор с безопасным сохранением); каждая option имеет label, value, order, active.
- Для text/number/boolean — options не показывать и не разрешать записывать.
- Существующие options должны оставаться доступными для редактирования/архивирования, даже если Attribute неактивен.
- Физическое удаление Attribute и Option в Filament отключено; архивирование — через `is_active`.
- Сохранить существующую проверку `is_admin`; не расширять доступ.
- Ошибки уникальности, пустых имён, неверных типов и запрещённой смены типа показывать понятно, не отдавать необработанные DB exceptions пользователю.

Если Filament RelationManager не позволяет удобно создавать options до сохранения Attribute, сначала сохранять Attribute, затем редактировать options. Не строить сложную транзакционную форму ради одного экрана.
