# BE-08.3.5 — Product Type ↔ Attributes: отчёт реализации

**Дата:** 2026-11-02  
**Результат:** реализация и автоматические проверки выполнены; окончательная приёмка остаётся за ручной проверкой интерфейса владельцем.

## Что реализовано

- Добавлена одна таблица `product_type_attribute`: составной первичный ключ `(product_type_id, attribute_id)`, `is_required` и `is_filterable` со значением по умолчанию `false`, `sort_order` со значением `0`, timestamps.
- Оба внешних ключа используют `RESTRICT`. Составной ключ блокирует повторное назначение на уровне БД; индекс `(product_type_id, sort_order, attribute_id)` поддерживает вывод назначений в заданном порядке. Индекс для `attribute_id` создаёт MariaDB при объявлении внешнего ключа.
- `ProductType::attributes()` и `Attribute::productTypes()` используют существующие модели и pivot-поля. Отдельная Pivot-модель не нужна: нет дополнительного поведения или состояния за пределами трёх колонок связи.
- В Filament 5 на Edit Product Type добавлен Relation Manager. Он показывает имя, code, type, unit, active и настройки связи; selector предварительно загружает до 50 активных незанятых Attributes, поиск по имени/code остаётся доступен. Флаги и порядок редактируются отдельно для каждой связи. Явный Detach требует подтверждения и не удаляет Attribute или его options.
- Серверная операция повторно проверяет, что выбранный Attribute активен и ещё не назначен. Повтор назначения и конкурентная ошибка уникальности преобразуются в понятную ошибку формы. Настройки изменения ограничены pivot-полями менеджера связи.
- Неактивные назначенные Attributes и неактивные Product Types остаются доступны для просмотра/редактирования; их назначения автоматически не удаляются. CRUD Product, значения характеристик, публичный API, фильтры и BE-08.4.1 не добавлялись.

## Проверки и БД

- Перед миграцией `migrate:status` показал новую миграцию Pending; после применения — Ran. Команда выполнялась внутри `backend` с `DB_DATABASE=potsandplanters_test`.
- Применена только `2026_11_02_000006_create_product_type_attribute_table`. Production и staging не использовались.
- Профильные тесты: `ProductTypeAttributeTest`, `ProductTypeAdminTest`, `AttributeAdminTest` — 16 passed, 140 assertions. После правки AttachAction для предварительной загрузки selector `ProductTypeAttributeTest` — 5 passed, 27 assertions.
- Полный backend suite после правки selector: 105 passed, 790 assertions.
- Pint `--test` для 6 затронутых PHP-файлов: PASS. Для `Attribute.php` потребовалась только перестановка импортов в соответствии с Pint.
- `git diff --check`: PASS.
- Первый профильный прогон выявил неверный вызов `orderByPivot()` в callback сортировки таблицы; исправлен на `orderBy('product_type_attribute.sort_order', ...)`, после чего прогон прошёл.

Проверены `AGENTS.md`, `docs/common/PROJECT_CONTEXT.md`, `docs/common/ROADMAP.md`, BE-08 ADR, schema design report и задания BE-08.3.3–BE-08.3.4. Фактический код использует `attributes.type` и `attributes.unit`; реализация сохранила эти имена. В общих документах BE-08 всё ещё описан как выполняемый/запланированный этап, а не как принятый; статус общих документов не менялся до ручной приёмки.
