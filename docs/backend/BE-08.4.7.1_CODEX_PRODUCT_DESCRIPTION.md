# BE-08.4.7.1 — Product Description (Codex)

## Цель
Добавить отдельное необязательное форматированное описание товара в Laravel/Filament, не смешивая его с SEO Meta Description и не затрагивая публичный сайт.

## Перед изменениями: обязательный read-only аудит
1. Прочитать `AGENTS.md`, актуальные `docs/common/PROJECT_CONTEXT.md`, `docs/common/ROADMAP.md`, соответствующие ADR и отчёты BE-08.4.*. Проверить `git status --short`, не изменять/не сбрасывать незакоммиченные файлы.
2. Проверить фактические `products` migrations, `Product`, `ProductResource`, Create/Edit lifecycle, News `RichEditor`, `NewsHtmlSanitizer`, `NewsArticle` и тесты. Если аудит обнаружит несовместимость с данным ТЗ — остановиться и сообщить, не импровизировать.
3. Проверить, что актуальная схема `Attribute.is_filterable` и ручные исправления сохранены; не изменять их в рамках задачи.

## Утверждённые решения
- `products.description`: nullable `LONGTEXT`, хранит **санитизированный HTML** RichEditor. Необязателен для draft и published.
- Filament 5: штатный `RichEditor`, по образцу News, без файловых вложений. UI-подпись на английском `Description` / `Product Description` согласно существующему стилю панели.
- Использовать существующий `NewsHtmlSanitizer` **без копирования реализации**. Если его API/правила привязаны к News, предложить минимальное безопасное переиспользование без масштабного рефакторинга. Не расширять разрешённый HTML без согласования. Отклонять небезопасные теги, атрибуты, схемы ссылок и потенциальный XSS.
- Санитизация на серверной границе сохранения, а не только в UI. Сохранённое описание безопасно для будущего рендера; при этом не объявлять будущий frontend-рендер безопасным без отдельной проверки.
- Не использовать описание как `seo_description`, не менять SEO Title, Meta Description, slug, URL registry, OG image, Google Search Preview или правила автогенерации SEO.
- Не импортировать OpenCart HTML; преобразование исторических описаний будет отдельно согласовано в BE-09.
- Не менять API, DTO, Next.js, mock, публичный дизайн, маршруты, Cart/Enquiry.
- Не менять поведение ошибки галереи Create: товар остаётся созданным, уведомление и восстановление через Edit.

## Реализация (узкий scope)
1. **БД:** новая forward-only миграция добавляет `description LONGTEXT NULL` в `products`; `down()` удаляет только эту колонку. Не редактировать старые миграции. Учесть MariaDB.
2. **Домен:** добавить `description` в `Product` fillable/casts по фактическому паттерну; серверная нормализация/санитизация при записи, включая прямое сохранение через модель/сервис в обход Filament. Пустое значение сохраняется как `NULL` (если это согласуется с текущим контрактом). Не менять другие поля и бизнес-инварианты.
3. **Filament:** отдельная логичная секция RichEditor в Create/Edit, с теми же доступными элементами разметки, что у News; без attachments и без второй реализации preview-компонентов. Сохранение и повторное открытие редактирования не должны ломать HTML.
4. **Тесты:** migration nullable; Create/Edit пустого описания для draft/published; сохранение и повторное чтение разрешённых тегов; удаление `<script>`, обработчиков событий, `javascript:` и других опасных конструкций; прямое сохранение вне Filament; независимость от SEO; сохранение существующих значений SKU/атрибутов/категорий/галереи. Использовать реальные правила существующего sanitizer, не придумывать расширенный whitelist.
5. **Документация:** обновить `docs/common/PROJECT_CONTEXT.md` и `docs/common/ROADMAP.md` только после подтверждённой реализации и тестов; добавить краткий `docs/backend/BE-08.4.7.1_IMPLEMENTATION_REPORT.md` с фактическими изменениями и ограничениями. Если документация содержит исторические решения, не переписывать историю без пояснения.

## Проверки и безопасность
- Миграции и тесты с записью — **только изолированная MariaDB `potsandplanters_test`** через предусмотренный Docker Compose. Не применять миграции к обычной dev, staging или production БД.
- Проверить `up → rollback → up` только в тестовой схеме; убедиться, что существующие продукты с `NULL` описанием остаются валидными.
- Запустить профильные Product/News sanitizer тесты, затем полный Laravel suite, Pint и `git diff --check`. Сообщить точные команды, количество тестов/assertions и ошибки. Если запуск невозможен — явно указать, что не проверено.
- Сохранить все незакоммиченные изменения; без `git reset`, `checkout`, удаления или перезаписи чужих правок. Изменять только файлы задачи и минимально необходимые тесты/документацию.

## Критерии приёмки
- Администратор может создать и отредактировать товар с пустым либо форматированным Description.
- Разрешённая разметка сохраняется и корректно открывается в RichEditor; опасный HTML не сохраняется как исполняемый.
- Product Description независим от SEO Meta Description, не влияет на публикацию и URL.
- Ничего не меняется в публичном API/Next.js, атрибутах, категории, галерее и заявках.
- Миграционный цикл и тесты подтверждены в `potsandplanters_test`; отчёт отделяет автоматические проверки от ожидаемой ручной проверки Filament.
