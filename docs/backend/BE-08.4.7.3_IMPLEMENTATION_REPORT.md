# BE-08.4.7.3 — Card Display Attributes + Live Product Card Preview

## Статус

Реализовано и автоматически проверено. Ручная визуальная приёмка владельцем не выполнена; этап не считается принятым до неё. BE-08.4.7.4 и BE-08.5 не начинались.

## Read-only аудит перед изменениями

- `ProductResource` уже включал описание, SEO, Product Type, optional selections, typed values и Create-only gallery uploads; `CreateProduct` и `EditProduct` сохраняли Product и значения через транзакционный `ProductCategoryManager` / `ProductAttributeValueManager`. `EditProduct` восстанавливал selection из legacy typed values. Существующие незакоммиченные ручные изменения в этих файлах и моделях сохранены.
- `Product` хранит цену в decimal cast и имеет галерею через `ProductImage → MediaAsset`; пригодный URL доступен только для ready asset variants. Create загружает файлы без немедленного создания готового MediaAsset, Edit управляет готовой галереей отдельным relation manager.
- `Attribute` уже имел `name`, `code`, `type`, `unit`, `is_active`, `is_filterable`, options и Product Type assignments; эквивалентного `short_label` не было.
- Публичные источники карточки: `CatalogCard` / `ProductCardDetails` и `Home ProductCard` / `ProductCardDetails`. Обе карточки используют квадратное изображение, `Model: SKU`, имя, одну строку спецификаций, цену (`Price on enquiry` для NULL) и `View product ↗`. Каталог оборачивает её ссылкой, но действия и ссылку в Filament preview не включали.
- Публичный форматтер знает диаметр и высоту как отдельные типизированные поля и поэтому соединяет их через ` × ` с `cm`; общая Attribute metadata не содержит группы/геометрии. Для произвольных Attributes не выводятся `Ø`, `H`, `L`, `W` по имени. Применён единый разделитель ` · `.

## Реализация

- Добавлена миграция `2026_11_02_000017_add_product_card_display_configuration`: nullable JSON `products.card_display_attribute_ids` и nullable `attributes.short_label` длиной до 32. Старые продукты получают `null` и пустой display list; ручные копии названий или значений не сохраняются.
- ProductResource предоставляет reorderable список атрибутов карточки только из текущего Product Type, которые обязательны, выбраны или имеют legacy/saved values. Серверная транзакция отвергает некорректные ID, дубликаты, чужие/невыбранные optional Attributes. Обязательные атрибуты допустимы без optional assignment. Existing value manager продолжает защищать значения и legacy selections.
- Edit восстанавливает порядок ID при открытии. Перестановка сохраняется вместе с Product и selections в существующей транзакции. Смена Product Type при наличии values/assignments остаётся заблокирована существующим контрактом; несоответствующий display list при переходе отклоняется.
- В AttributeResource добавлен необязательный Short label. Модель обрезает пробелы, удаляет HTML tags и валидирует длину. Числа сохраняются форматтером как десятичные строки; boolean выдаётся как Yes/No, select/multiselect — labels options, multiselect следует порядку выбранных ID. `0` и `false` не теряются, пустые значения пропускаются.
- Новый `ProductCardSpecificationsFormatter` формирует данные preview без изменения публичного DTO/API. Для текстовых, числовых и boolean атрибутов label — `short_label` либо имя Attribute; для select/multiselect показывается только label выбранной option. Number unit берётся только из `Attribute.unit`.
- Filament preview повторяет размеры карточки, фон, отступы и типографическую иерархию каталога; показывает изображение только от ready main MediaAsset, SKU, имя, упорядоченные спецификации и цену. В нём нет публичной ссылки или действия.
- В Create нет готового MediaAsset до сохранения и фоновой обработки. Если пользователь уже добавил файл, preview честно показывает `Image available after save and processing`; иначе `No ready main image`. Edit использует готовый main variant либо placeholder. Поля SKU/имени/цены и типизированные значения реактивны при изменении/blur, selections и порядок — live.
- Next.js, публичный API, SEO, маршруты и публичные стили не изменялись.

## Состояние схем и ручная приёмка

- `potsandplanters_test`: migration 000017 применена; цикл up/rollback/up пройден.
- Обычная локальная dev schema `potsandplanters`: migration 000017 имеет статус `Pending`; её не применяли.
- Production schema не проверялась и не менялась.
- Автотесты подтвердили сохранение порядка, валидацию дубликатов/foreign/unselected ID, fallback label, options labels, пустые значения, ноль, false и точность decimal строки. Полный suite подтверждает отсутствие выявленной регрессии backend.
- Ручной чек-лист владельца: на Create проверить пустой preview и честный placeholder при загруженном временном файле; на Edit проверить main image; сравнить визуально с `CatalogCard` и `Home ProductCard`; изменить имя/SKU/цену, value, selection и порядок; сохранить/переоткрыть и подтвердить порядок; проверить Price on enquiry; проверить круглый и прямоугольный товар без эвристик по имени. До этой проверки полная визуальная приёмка не заявляется.

## Ограничения

- Для новых несохранённых файлов Create не показывает временную картинку; требуется сохранение и завершение media processing.
- Общая модель не содержит явной dimension-group metadata, поэтому спецификации используют единый ` · `; группировка ` × ` не угадывается.
- Никакие тестовые/примерные значения или изображения не добавлены в продуктовые записи.

## Дополнение по единицам атрибутов

После первоначальной реализации добавлена поддержка редактируемой единицы для всех типов Attribute. Migration 000018 переносит прежние `NULL` в `cm`, задаёт `cm` как обязательный database/model/form default и снимает прежнее ограничение `unit` только для `number`. Для нечисловых значений formatter сохраняет labels без суффикса единицы; числовые значения и preview используют сохранённый unit.

В публичном Next.js formatter спецификаций заменён жёсткий суффикс на optional `diameterUnit` / `heightUnit` с `cm` fallback. Это сохраняет текущий вид карточек и Product Detail Page и подготовляет их к будущему DTO mapping. API пока отсутствует, поэтому custom units из backend пока не поступают в Next.js. Migration 000018 применена и проверена циклом up → rollback → up только в `potsandplanters_test`. Первая попытка владельца в локальной `potsandplanters` остановилась на UPDATE: существующий `attributes_unit_type_check` не позволил записать `cm` для нечислового атрибута. Порядок migration исправлен: constraint снимается до заполнения единиц. Ошибка возникла на первом SQL statement, поэтому migration не записалась как выполненная и частичных изменений не было; в dev её повторно не запускали. Этот последующий unit follow-up добавлен после перечисленных выше прогонов; отдельные application tests и frontend checks для него не запускались.
