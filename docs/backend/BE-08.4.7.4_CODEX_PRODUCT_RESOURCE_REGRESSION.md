# BE-08.4.7.4 — ProductResource: финальная регрессия и приёмка

## Цель
Проверить совместную работу реализованных BE-08.4.7.1–.3 и ранее принятых модулей BE-08.4. Закрыть подтверждённые регрессии точечными исправлениями. **Не добавлять новую функциональность** и не начинать BE-08.5.

## 0. Обязательный read-only аудит перед любыми изменениями
1. Прочитать `AGENTS.md`, `docs/common/PROJECT_CONTEXT.md`, `docs/common/ROADMAP.md`, релевантные отчёты BE-08.4.7.1–.3 и архитектурные решения.
2. Зафиксировать `git status --short`, незакоммиченные изменения и фактические миграции/модели/Filament-компоненты. Сохранить ручные правки; никаких `reset`, `checkout`, очисток или массового рефакторинга.
3. Проверить реальные команды Docker Compose и изоляцию тестовой MariaDB. Не считать устаревшие файлы handoff доказательством текущего состояния.
4. Отдельно проверить фактическую реализацию единиц измерения числовых Attribute и Card Preview: это ручное изменение владельца, его нельзя потерять.

## 1. Область регрессии
### Product Core / Create / Edit
- Brand, Supplier, Product Type, SKU (нормализация, уникальность в пределах Brand), Series того же Brand, nullable положительная AED price.
- Draft vs Published, обязательные категории и Primary Category, атомарность сохранения, сохранность Product ID, slug/SEO и истории URL.
- RichEditor Product Description: nullable LONGTEXT, разрешённое форматирование, безопасная санитизация, очистка пустого HTML в NULL, отсутствие влияния на SEO Meta Description.

### Selectable Attributes
- Product Type задаёт допустимые атрибуты; required нельзя отключить и он проверяется при публикации.
- Optional: не выбран / выбран пустой / выбран заполненный; состояние переживает Create/Edit/reload.
- Для разных геометрий проверить Diameter+Height и Length+Width+Height.
- Все пять типов значений, включая boolean false, decimal 0 и 0.123456, select/multiselect, неактивные ранее сохранённые варианты.
- Нельзя снять заполненный optional без предварительной очистки и отдельного сохранения; блокировка смены Product Type при values или optional assignments; legacy values восстанавливают assignments.
- `is_filterable` глобально принадлежит Attribute, не pivot Product Type; category filters не изменяются.

### Card Display / Preview
- Выбор только применимых выбранных атрибутов, уникальность, порядок и сохранение после reload; значения не копируются в конфигурацию.
- Short Label, единицы измерения numeric attributes, корректная decimal precision, пустые значения без лишних разделителей, безопасный вывод строк.
- Реактивность preview на Name, SKU, price, attributes/order, image; отображение nullable price и отсутствующего/не готового изображения без фиктивных данных.
- Сравнить с существующими `frontend` ProductCard/ProductCardDetails/format-specifications по визуальным элементам. **Не менять публичный дизайн** и не требовать абсолютной идентичности разных UI-движков; зафиксировать реальные отличия.

### Gallery / SEO
- Create с несколькими изображениями, main и ALT; Edit reorder/main/ALT/detach/shared asset/Retry/status; pending/failed/ready и отсутствие утечки private originals.
- При ошибке прикрепления на Create **сохранить принятое поведение**: товар создан, постоянное уведомление и восстановление через Edit.
- Общий Google Search Preview, SEO overrides, OG image, canonical Primary Category; не внедрять авто SEO и HTTP 301 (Nginx/BE-09).

## 2. Проверки и среда
1. Выполнить профильные backend-тесты по ProductResource, Description, Attributes, Gallery, Card Display, SEO и Category Filters; затем полный Laravel suite.
2. Выполнить Pint, `git diff --check`; frontend typecheck / relevant tests / build — если предусмотрено AGENTS.md и доступно через Compose, без изменения frontend.
3. Проверить миграционную последовательность и схему **только в `potsandplanters_test`**. Обычная dev-схема содержит pending миграции 000016 и последующие: **не применять** их без отдельного разрешения владельца. Production/staging миграции запрещены.
4. Проверить Blade-specific formatter/lint; если Node/Bun отсутствует в backend-контейнере, выяснить допустимый путь через существующий Compose frontend/runtime, не устанавливать новые зависимости только ради проверки. Если невозможно — явно зафиксировать непроверенный пункт, не заявлять PASS.
5. По возможности проверить количество SQL-запросов галереи/OG selector и исправлять только доказанную существенную проблему; не расширять scope оптимизаций.
6. Все тестовые данные создавать/удалять только в изолированной тестовой БД, не трогать данные владельца.

## 3. Ручная приёмка владельцем
Подготовить короткий воспроизводимый checklist Filament: Create draft, Create published, Description formatting, Round/Square optional attributes, values protection, Card Display order/units/live preview, nullable price/image, gallery Create/Edit/failure recovery, SEO/OG, reload persistence. Отдельно указать, какие пункты реально проверены автоматически и какие требуют браузера/владельца. Не объявлять ручную приёмку пройденной самостоятельно.

## 4. Ограничения
- Никаких изменений публичного API, Next.js, маршрутов, SEO-автогенерации, Nginx 301, импорта OpenCart или новой функциональности.
- Не делать production/dev миграции и не менять конфигурацию окружений без разрешения.
- Не вводить mock fallback, не выдумывать товарные данные, не менять утверждённый стек.
- Любые исправления — минимальные, с тестами; при архитектурной неоднозначности остановиться и запросить решение.

## 5. Критерии приёмки
- Профильный и полный backend suite PASS, Pint и `git diff --check` PASS, миграции/rollback проверены в изолированной тестовой БД или обоснованно указано ограничение.
- Подтверждена сохранность ручных изменений и ранее реализованных функций.
- Все найденные дефекты классифицированы; критические исправлены и повторно проверены, остальные вынесены в отчёт с приоритетом.
- Подготовлены `docs/backend/BE-08.4.7.4_IMPLEMENTATION_REPORT.md` и checklist ручной приёмки; `PROJECT_CONTEXT.md` и `ROADMAP.md` обновлять **только с честным статусом** «автоматически проверено / ручная приёмка ожидается» до подтверждения владельца.
- Не объявлять BE-08.4 и BE-08.4.7 полностью закрытыми до подтверждения владельца.
