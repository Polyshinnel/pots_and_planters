# BE-08.4.7-AUDIT — Read-only аудит ProductResource перед финальной доработкой

## Цель
Зафиксировать фактическое состояние административной карточки товара Laravel 13 / Filament 5 после BE-08.4.1–08.4.6, включая ручные исправления владельца, и подготовить узкий, проверяемый план BE-08.4.7. **Это только аудит, не реализация.**

## Источники и приоритет
1. Фактический репозиторий и рабочее дерево, `AGENTS.md` (включая вложенные), `docs/common/PROJECT_CONTEXT.md`, `docs/common/ROADMAP.md`.
2. `docs/backend/BE-08_ARCHITECTURE_DECISIONS.md`, отчёты BE-08.4.1–08.4.6, соответствующие тесты.
3. История задач — справочный материал; при расхождениях с кодом явно указать расхождения. Не считать прикреплённый старый PROJECT_CONTEXT актуальнее репозитория.

## Ограничения
- Строго read-only: не изменять файлы, миграции, схемы БД, конфигурацию, lockfiles, не выполнять formatters с записью, не создавать коммиты, не делать reset/clean. Не запускать команды, способные менять данные. Разрешены безопасные чтение, git status/diff, анализ тестов и конфигурации.
- Не трогать production/staging/dev БД. Не запускать миграции. Сохранить все незакоммиченные изменения.
- Не менять Next.js, публичный дизайн, API, SEO-правила, маршруты и редиректы. Исторические 301 отложены до сопоставления старых и новых URL и настройки nginx при BE-09. Правила автогенерации SEO — на этапе наполнения каталога.
- Не предлагать смену утверждённого стека: Next.js 16, React 19, TypeScript, Mantine 9, Laravel 13, Filament 5, MariaDB, Redis, Horizon.

## Проверки аудита
1. **ProductResource UX**: Create/Edit, секции/вкладки, порядок полей, состояние валидации, ошибки, сохранение draft/published/archived, обязательные Brand/Supplier/Product Type, Series, SKU, AED price, категории и primary.
2. **Attributes**: динамические поля всех пяти типов, required при публикации, сохранение false/0/decimal, inactive options, запрет потери данных при смене Product Type, проверка транзакционности.
3. **Category filters и ручные изменения**: найти действительный источник `is_filterable` (по решению владельца — глобально на Attribute), проверить, не осталось ли использования `product_type_attribute.is_filterable` в модели, Filament, запросах, валидации, тестах и миграциях. Указать безопасный путь согласования схемы, если найдены расхождения; **не исправлять в аудите**. Убедиться, что фильтры категорий не дублируют значения товаров.
4. **Gallery**: добавление изображений при Create и Edit, общий MediaAsset, main/order/ALT, async WebP 1000/250/100, статусы pending/processing/ready/failed, Retry и права, отсутствие удаления shared assets при отвязке. Проверить, нет ли неудобных или конфликтующих сценариев между Create Repeater и Edit Relation Manager.
5. **SEO**: существующий общий Google Search Preview, SEO Title, Meta Description, OG, Slug, canonical/URL history. Не дублировать компоненты. Отдельно зафиксировать, что правила автогенерации SEO и nginx 301 вне BE-08.4.7.
6. **Качество и риски**: повторяющийся UI-код, N+1, чрезмерная загрузка изображений, неконсистентные разрешения/валидация, неожиданные side effects, доступность и читаемость интерфейса. Предлагать только минимальные адресные улучшения.
7. **Тесты**: определить существующее покрытие, конкретные пробелы, какие профильные и полные тесты следует запускать после изменений. Тесты в этом аудите не запускать, если их выполнение может изменять БД/файлы/Redis; указать безопасный план запуска в `potsandplanters_test`.

## Результат
Подготовить `docs/backend/BE-08.4.7_AUDIT_REPORT.md` **только если владелец отдельно разрешит запись отчёта в репозиторий**. Пока выдать отчёт в ответе Codex без изменения файлов:
- таблица «проверено / обнаружено / риск / приоритет / файл:строка»;
- отдельный раздел «ручные изменения владельца, которые нельзя потерять»;
- противоречия между документацией, схемой и кодом;
- предлагаемый минимальный scope BE-08.4.7, разбитый на 2–4 небольших проверяемых подэтапа, каждый с целью, изменениями, ограничениями и критериями приёмки;
- чек-лист ручной проверки Filament;
- список вопросов, если решение нельзя обоснованно принять без владельца.

## Критерии завершения аудита
- Ни один файл и ни одна БД не изменены; `git status --short` до и после совпадают.
- Каждый существенный вывод подтверждён ссылкой на существующий файл/строки.
- Текущие ручные правки по `is_filterable` и Create Gallery явно учтены.
- Никакая реализация BE-08.4.7 или BE-08.5 не начата.
- После аудита остановиться и дождаться согласования конкретного плана реализации.
