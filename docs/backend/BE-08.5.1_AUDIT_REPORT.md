# BE-08.5.1 — Read-only аудит Product API

Дата аудита: 2026-11-09. Статус: аудит завершён; архитектурное согласование ожидается. Код, схемы и существующие документы не менялись.

## Итог

Laravel уже содержит Product domain, административное управление, медиаобработку, категории/фильтры, typed attributes и URL resolver. Публичных Product API routes нет. Next.js Shop и Product страницы всё ещё читают `frontend/src/data/catalog.mock.ts` через `frontend/src/lib/catalog/repository.ts`; это включая enquiry line resolution. Категории для shop уже берутся из Laravel API, поэтому страница частично real/частично fixture.

Согласно переданной информации владельца, 2026-11-09 вручную принята BE-08.4.7.4 и BE-08.4 принят локально. Это обновляет прежнюю пометку ожидания ручной приёмки в handoff, но не означает deployment/activation в production. `PROJECT_CONTEXT.md` и `ROADMAP.md` в рамках аудита не редактировались.

Маршруты сейчас: `backend/routes/api.php` содержит `/v1/categories`, `/v1/catalogues`, `/v1/contacts`, `/v1/news`, `/v1/page-seo`, `/v1/enquiries` и health. Product routes отсутствуют. `CategoryController` отбирает published categories и ставит `Cache-Control: no-store`; DTO содержит `public_id`, slug/path, content и image/SEO URL.

Индексы уже есть: Product UUID, `(brand_id, sku)`, `(status, updated_at, id)`, глобальный unique slug; pivot category PK `(product_id, category_id)` и индекс category; Product attribute unique `(product_id, attribute_id)`, selection uniqueness, media order `(product_id, sort_order, id)`, one-main unique, URL alias unique path и product index, category filter `(category_id, sort_order, attribute_id)`. Фильтрация по нескольким typed values/facets может потребовать query plan/index review; новую оптимизацию до измерения не утверждать.

## Поля и преобразования

| Laravel source | Публичный Product DTO | Преобразование/ограничение |
|---|---|---|
| `products.public_id` UUID | `id` | Стабильный public ID; не expose numeric DB ID |
| `sku`, `name` | `sku`, `name` | SKU уже нормализуется моделью; уникальность только в Brand |
| Brand/Supplier/ProductType/Series relations | `brand`, возможно `supplier`/`productType`/`series` | Рекомендуется публично вернуть Brand и product type only as needed; inactive policy unresolved; supplier обычно не нужен UI, не раскрывать без необходимости |
| `status` | DTO не содержит статус; список только published | `archived`/`draft` исключать; Supplier/Brand inactive semantics требуют approval |
| `price_aed` decimal:4 | `priceAed: string|null`, `currency:'AED'` | JSON string, никогда float. Null = Price on enquiry; валидная цена >0 |
| categories + primary category | `categoryIds`, `primaryCategory`, `canonicalPath` | Публичные category IDs = `categories.public_id`; выдавать Product только по опубликованным категориям; canonical строить resolver-ом |
| slug | `slug`, `canonicalPath` | Globally unique slug; API lookup slug без redirect; path `/shop/{primaryCategory.slug}/{slug}` только когда product+primary category published |
| description | `descriptionHtml: string|null` | Санитизированный HTML; на FE нужен безопасный rendering договор |
| seo title/description/OG | `seo.title`, `seo.description`, `seo.ogImage` | Title override или name; description override nullable (не утверждать авто-generated copy); OG ready override иначе ready main variant |
| media assets + product image | gallery `{url,alt,order,isMain}` | Только ready существующие variant URL; недоступный variant исключить; placeholder на frontend только для отсутствующего изображения |
| values/selections/assignments | typed `attributes[]` (code/type/label/value/unit/options) | Отдавать только применимые required + выбранные optional; пустые значения не выдавать; stale/inactive labels требуют policy |
| card IDs + short_label + unit | `cardSpecifications[]` structured и/или `displayText` | Один авторитетный backend formatter; текущая Next formatter другая, унифицировать после approval |
| Category filter pivot | `filters[]`/facets для category products | Порядок/type из category config; options/count вычисляются только по доступным products |

## Расхождения документов и кода

1. Переданное задание и текущий `PROJECT_CONTEXT.md`/`ROADMAP.md` описывают Product API как отсутствующий — это подтверждается `routes/api.php`.
2. Документы отмечают ожидание ручной приёмки BE-08.4.7.4; задача задаёт более новое подтверждение владельца от 2026-11-09. Будущее обновление документов должно отразить локальную приёмку, не production.
3. Документы упоминают текущий Next product mismatch redirect как 308; код в `frontend/src/app/shop/[category]/[slug]/page.tsx` вызывает Next `permanentRedirect`, что соответствует 308-стилю, но не Laravel resolver/301. Задание исключает 301 из BE-08.5; BE-09 отдельно.
4. Некоторые исторические handoff формулируют `published` как будущий публичный статус, это верно сегодня: нет API scope/route. Public visibility должна быть заново чётко задана в DTO/use case.
5. Старые mock types используют `priceAed:number|null`, `ProductSpecifications` legacy keys и 4 статических facet keys; Laravel хранит точный decimal string и динамические attributes. Прямого совместимого mapper нет.

## Риски и open decisions

- Активность Brand/Supplier/ProductType/Series/Attribute/Option и фильтрация опубликованного Product не имеют единой согласованной public policy.
- `ProductUrlResolver::resolve()` различает canonical/alias/secondary/not_found и возвращает canonical path, но alias ownership для archived product даст 404; это надо закрепить для detail lookup. Resolver не должен 301ить в BE-08.5.
- Фильтр категорий должен учитывать товары, где category secondary; не смешивать несопоставимые Product Types. AND/OR, ranges, option keys, zero/false, no-filter values и facet counts не полностью определены.
- Нет публичного Product API query plan/serialization; eager loading нужен, иначе relation graph создаст N+1.
- `no-store` принят для существующих APIs; стратегия cache/revalidation для каталога пока не утверждена.
- `robots:index:false` на текущих Product details; желаемая индексация и SEO metadata/canonical production behavior требуют решения.
- Home featured products и search ещё имеют независимые fixture sources.
- Наличие товаров в production/staging, privacy/media storage URLs и legacy URL history coverage требуют BE-09; production status не аудировался.
