## Этап 0. Read-only preflight

**Цель:** установить реальное состояние перед кодом.

**Действия:** прочитать AGENTS/docs, `git status --short` и diff всех затронутых ручных изменений, routes/api.php, Product/Category/Supplier/Attribute/Media models, ProductUrlResolver, ProductCardSpecificationsFormatter, существующие API response/error patterns, миграции и тесты. Проверить текущую test DB изоляцию и наличие миграций, ничего не мигрировать. Составить краткую таблицу «контракт ↔ текущая модель», зафиксировать противоречия. Если для реализации обязательного правила отсутствует определённая структура данных/совместимость — остановиться и запросить решение, не придумывать.

**Критерий:** нет неожиданных изменений существующих файлов, есть план минимального diff.

## Этап 1. Visibility и query layer

**Цель:** публичный scope Product без дублирования условий.

**Изменения:** query/service для `published` Product, опубликованной Primary Category, активного Supplier; не скрывать по активности Brand/ProductType/Series/Attribute/Option. Для category list — опубликованная association включая secondary; global list — опубликованная Primary. Global slug detail и canonicalPath от существующего resolver. `newest` и прочие сортировки, стабильный tie-break, `NULL` prices last; pagination SQL до загрузки DTO. Оптимальный eager loading, не N+1.

**Ограничения:** не трогать Filament, Product model rules, URL registry, redirect, миграции, индекс без отдельного согласования.

**Приёмка:** тесты visibility, secondary category, inactive supplier, inactive definitions, unknown slug, pagination/sort и query-count.

## Этап 2. DTO и media/SEO

**Цель:** строго типизированная публичная сериализация.

**Изменения:** GET `/api/v1/products`, GET `/api/v1/products/{slug}`; отдельные Laravel Resources/DTO для list/detail и связанных полей. Public UUID, exact decimal strings, nullable fields, Brand, primary/category IDs, `canonicalPath`, sanitized description, ручное SEO/noindex, ready media variant fallback, typed attributes и option labels, ordered card specs через существующий formatter. `Cache-Control: no-store`.

**Ограничения:** не отдавать Eloquent напрямую; не раскрывать DB PK, Supplier internals, original paths, media generation tokens. Не добавлять фальшивые данные, `featured`, ProductVariant, auto SEO.

**Приёмка:** shape contract tests, precision 0/false/0.000001, price NULL, ready/pending/failed/missing variants, OG override/fallback, HTML sanitization, noindex, private data exclusion.

## Этап 3. Filter grammar/facets и legacy compatibility

**Цель:** выполнить утверждённый контракт без изменения frontend.

**Изменения:** category-scoped `filter[code]`, typed value validation, inclusive decimal range, AND across/OR within, counts after all filters, nonzero facet options, category filter config/global filterable/active definition eligibility. Legacy query keys только через **проверяемый explicit mapping** на реальную category config; ни одного invented mapping. Неизвестные, конфликтующие, неоднозначные запросы → 422. SQL filtering before pagination; EXPLAIN/query-count на тестовых fixtures.

**Ограничения:** если конкретные legacy values нельзя однозначно сопоставить без решения владельца — оформить как открытый вопрос и не заявлять полную URL-совместимость. Не добавлять индексы и миграции автоматически. Не изменять category endpoints.

**Приёмка:** feature tests по всем пяти типам, zero/false, range boundaries, inactive options, mixed Product Types, secondary category, counts, invalid keys/values, URL mapping/conflict.

## Этап 4. Errors, regression и отчёт

**Цель:** подтверждённый API без побочных изменений.

**Изменения:** только для новых Product routes нормализованный `{error:{code,message,requestId,errors?}}`, безопасная обработка 404/422/503; существующие API не менять. Обеспечить `200 []` отдельно от 404 и 503. Подготовить `docs/backend/BE-08.5.2_IMPLEMENTATION_REPORT.md` с точным перечнем файлов, DTO, endpoint examples на синтетических данных, SQL/query-count, отклонениями от контракта и незакрытыми вопросами.

**Проверки:** профильные и полные Laravel tests только в Docker Compose с `potsandplanters_test`; Pint для затронутых PHP; `git diff --check`; `php artisan route:list --path=api/v1`; тесты request validation, exact strings, no-store, response errors, 404, visibility и SQL count. Проверить изоляцию БД до тестов. Миграции/rollback только в test DB и только если действительно необходимы и разрешены условиями; никакой dev/prod migration. Не запускать frontend build без необходимости: frontend вне scope.

**Stop condition:** завершить backend API, тесты и отчёт; **остановиться**. Не начинать BE-08.5.3/4/5, не подключать Next.js, не активировать Product/Cart Enquiry, не выполнять production deployment.

Если весь filter/facet слой требует существенного изменения согласованного плана, разбить работу на небольшие внутренние проверяемые commits/подэтапы без расширения scope и описать это в отчёте. Не заявлять BE-08.5.2 завершённым, если обязательная часть контракта не реализована/не проверена; явно сообщить blocker. Сохранять ручные uncommitted изменения и не делать лишний рефакторинг.
