**Статус:** Product Read API реализован. Полный backend suite завершился с одной ошибкой в ранее изменённой вручную логике выбора Product Attributes; см. результаты ниже. BE-08.5.3 не начинался.

До правок прочитаны `AGENTS.md`, `PROJECT_CONTEXT.md`, `ROADMAP.md`, утверждённый Product API contract, BE-08.5.2 instructions, BE-08 architecture decisions и артефакты BE-08.5.1. Проверены ручные изменения `git status`/diff, API routes, модели, URL resolver, formatter и миграции. В тестовой схеме миграции 000001–000018 отмечены `Ran`; миграции этой задачей не запускались. Все тестовые команды задавали `DB_DATABASE=potsandplanters_test`, а `backend/phpunit.xml` принудительно устанавливает это же имя.

В исходных данных нет подтверждённых URL mappings для старых ключей `material`, `color`, `size`, `usage`. Запросы с legacy keys сейчас получают `422`, пока владелец не утвердит реальные соответствия.

## Реализация

- `GET /api/v1/products`: опубликованный Product, активный Supplier и опубликованная Primary Category; в category scope учитывается опубликованная secondary association. Пагинация SQL-side, стабильная сортировка, `NULL` price в конце. Unknown/unsupported parameters и недопустимые фильтры возвращают envelope `422`.
- `GET /api/v1/products/{slug}`: глобальный slug lookup, одинаковый `product_not_found` для недоступных и неизвестных товаров. Alias resolution и redirect не затронуты.
- DTO `ProductListData`, `ProductDetailData`, `ProductSpecificationData` отдают только публичные UUID и безопасные поля; нет DB PK, данных Supplier, private media paths или технических токенов. Цена и numeric Attribute values остаются строками.
- Media доступны только при `ready` status и физическом наличии WebP variant: card image — card → thumb; gallery — full → card → thumb. Pending/failed/missing assets пропускаются или дают `null`.
- Detail отдаёт сохранённые typed Attribute values и option labels, описание после существующей санитизации, ручные SEO overrides, canonical path от `ProductUrlResolver`, `noindex,follow` и готовый OG override/fallback. Автогенерации SEO description нет.
- Category filters используют `filter[code]`, typed values, exact text equality, inclusive decimal range, OR внутри одного атрибута и AND между атрибутами. Facet counts считаются после действующих фильтров и до pagination; inactive definitions/options исключены из новых filter values.
- Обе новые GET routes устанавливают `Cache-Control: no-store`. Ошибки API используют `{error:{code,message,requestId,errors?}}`; database query failures преобразуются в безопасный `503`.

## Проверки

Все тесты выполнены через Docker Compose backend service и только с `potsandplanters_test`.

- `ProductReadApiTest` — **4 passed / 44 assertions**: DTO shape и sanitization, no-store header presence, visibility, secondary categories, сортировка, 404/422, decimal range boundary, пустой список, отсутствие роста SELECT query count при росте товаров с 1 до 3.
- Профильный запуск `ProductReadApiTest` + `ProductAdminTest` — **13 passed / 117 assertions**.
- Полный `php artisan test --compact` — **187 passed, 1 failed / 1334 assertions**. Единственный сбой: `ProductAttributeValuesTest::test_unselecting_a_filled_attribute_is_blocked` ожидает блокировку снятия заполненного Attribute. Актуальная незакоммиченная ручная правка `backend/app/Services/ProductAttributeValueManager.php` удаляет эту блокировку и сохраняет новый режим снятия; файл и тест не изменялись в этой задаче.
- Pint для 9 затронутых PHP-файлов — **PASS**.
- `php artisan route:list --path=api/v1` — **PASS**, зарегистрированы только GET/HEAD Product routes.
- `git diff --check` — **PASS**.

## Отклонения и незакрытые проверки

- Legacy key mapping намеренно не включён без подтверждённой category configuration.
- На тестовых fixtures подтверждены выдача, диапазон number filter и query count, но полный набор combinations всех пяти Attribute types и вариантов media (ready/pending/failed/missing/manual OG) отдельными новыми assertions не покрыт. Реализация следует существующим схемам и formatter/sanitizer; это остаётся ограничением автоматической evidence этого этапа.
- `Cache-Control` содержит директиву `no-store`; Laravel/Symfony также добавляет `private`.
- Production DB/deployment, миграции, Next.js, публичный дизайн и пользовательские маршруты не менялись. Product/Cart Enquiry не активировались.

Работу остановить до отдельного разрешения на BE-08.5.3.
