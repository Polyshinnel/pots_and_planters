# BE-08.5.3 — Дополнение к ТЗ Codex после контрольной точки A

**Статус:** решения владельца утверждены 10.11.2026; **это разрешение продолжить только BE-08.5.3**, а не подтверждение реализации или production-релиза.

**Основное ТЗ:** `docs/frontend/BE-08.5.3_CODEX_NEXTJS_PRODUCT_INTEGRATION.md` (если файл хранится в другом месте — найти фактический путь в репозитории). **Контракт:** `docs/backend/BE-08.5_FINAL_PRODUCT_API_CONTRACT.md`. Настоящее дополнение уточняет пункты C/D основного ТЗ; все остальные ограничения, контрольные точки и проверки сохраняются. При противоречии новых решений с формулировками «требуется согласование» в основном ТЗ использовать решения ниже. При расхождении с реальным кодом — остановиться и сообщить.

## 1. Утверждённые решения владельца

1. **Главная / Featured Products:** использовать восемь новейших доступных опубликованных товаров из Product API: `sort=newest&perPage=8`. Не добавлять `featured` поле, ручную подборку, фиктивные товары или цены. Существующий слайдер и его визуальная структура сохраняются. При 0 товарах — честное пустое состояние/отсутствие карточек без mock; при ошибке API — явное error state, не пустой успешный результат. Текущий заголовок секции не переименовывать без отдельного разрешения; в отчёте указать, что подборка фактически «новейшие», а не редакционно отобранные featured.
2. **Related Products:** максимум четыре **других** доступных товара из primary category текущего товара; сортировка `newest`, исключение по Product `public_id`. Использовать существующий list endpoint с `category=<подтверждённый формат из Laravel>`; запросить ограниченную страницу, достаточную для исключения текущего товара (обычно `perPage=5`, если API поддерживает), не загружать весь каталог. Если после исключения 0 товаров — скрыть секцию, не подставлять mock. Не создавать related API, не выдумывать связи. Если невозможно гарантировать 4 без дополнительной страницы, допускается меньше 4; зафиксировать. При ошибке API не показывать фиктивную секцию; предусмотреть наблюдаемую ошибку, не скрывать её как «0 related».
3. **Фильтры до BE-08.5.4:** временно отключить интерактивные фильтры и их неподтверждённые значения/counts; сохранить layout и дизайн насколько возможно, не оставлять активные контролы, имитирующие фильтрацию. Не использовать `catalog.mock.ts` и не вычислять фильтры на клиентских fixtures. Новые `filter[code]` и старые `material/color/size/usage` при наличии в URL **не удалять и не игнорировать молча**: явно показать английское сообщение о временной недоступности фильтрации и не показывать нефильтрованную выдачу как будто фильтр применён. Не отправлять legacy keys в backend при пустом mapping. Не придумывать mappings. Реализацию динамических facets и legacy compatibility отложить до BE-08.5.4.
4. **Сортировка:** default `newest`; поддержать `newest`, `name-asc`, `name-desc`, `price-asc`, `price-desc` с реальной backend-сортировкой и пагинацией. Старое `sort=featured` — **явный Next.js redirect** на `sort=newest` с сохранением других query params (включая legacy filters и `page`, если присутствует), без зацикливания. Не использовать mock sort. Для иных неподдерживаемых sort значений — явная ошибка/validation state, не молчаливый fallback. Не менять согласованные redirects для product category mismatch и `/product/[slug]`; redirect `sort=featured` относится только к URL каталога и не заменяет BE-09 SEO 301.

## 2. Детали безопасной реализации

### 2.1. Объём подключения и запрет смешанных источников

- **Включено:** `/shop`, `/shop/[category]`, `/shop/[category]/[slug]`, `/product/[slug]`, их Product cards/details/related, главная Featured Products. Для каждого включённого runtime пути источник Product — **только** Laravel Product API; Categories API остаётся источником категорий.
- **`/solutions`:** явно **вне BE-08.5.3**. Не заменять там fixtures и не менять страницу, ссылки, CSS или её действия без отдельного решения. Отразить оставшуюся mock-зависимость и риск в отчёте. Если её runtime Add to Enquiry реально доступен и может выдавать фиктивный товар за настоящий, **остановиться с точным описанием риска и запросить разрешение на минимальное безопасное изменение**; не объявлять весь публичный сайт свободным от mock и не активировать/переделывать корзину самовольно.
- **Корзина `/cart`, `resolveEnquiryLine`, localStorage `potsandplanters.enquiry.v1`:** вне scope до BE-08.5.5. Не менять ключ SKU на UUID, не мигрировать localStorage, не обновлять payload, не включать Product/Cart Enquiry. Если кнопка/ссылка из подключённой страницы реально ведёт в mock-based flow, не маскировать это; проверить фактическую доступность и при риске — остановиться для отдельного решения. Не считать отключение отправки доказательством отсутствия фиктивных данных.
- **`/search`:** провести аудит фактической runtime Product-зависимости. Если поиск включён в BE-08.5.3 через общие компоненты и использует mock — не оставлять его незаметно под видом реального. Если перенос требует отдельного backend search контракта, зафиксировать как исключённый потребитель/блокер и запросить решение до изменения публичного поведения. Не реализовывать новый search API без согласования.

### 2.2. API, цены, изображения и SEO

- Вызовы только через существующий `serverApiFetch` и реальные DTO. Не менять Laravel Product API/DTO без отдельного согласования. `priceAed` — `string | null`, исходную точность не терять, `null` отображать как **Price on enquiry**, не как `0` или выдуманную цену. Проверить форматирование и сортировку именно на сервере.
- `canonicalPath` из API — авторитетная ссылка для карточек и metadata товара, включая вторичные категории. Сохранить существующий Next.js redirect при category mismatch (его фактический код и поведение), legacy `/product/[slug]`, `robots: noindex,follow`, ручные SEO/OG overrides, ALT, sanitized HTML. Не включать index и не вводить новые 301/308 для товарных маршрутов.
- Изображения — только ready URLs из DTO; при отсутствии использовать уже существующий placeholder. Никаких private paths.
- `404` товара, пустой `200` списка, `422` запроса и `503`/outage — разные состояния. Не превращать outage в пустой каталог, не скрывать ошибку через `catch => []`, `notFound()` или mock fallback.

### 2.3. URL фильтров и сортировки — порядок обработки

1. На страницах списка сначала нормализовать **только** `sort=featured` через redirect к `sort=newest`, сохраняя остальные query keys/values. Сохранять повторяющиеся параметры и корректное URL encoding; не терять `page` или legacy filters.
2. После нормализации при наличии **любых** временно неподдерживаемых фильтров (`material`, `color`, `size`, `usage`, `filter[code]` или иных подтверждённых audit-ом фильтров) показать явное состояние «Filters are temporarily unavailable» с возможностью **осознанно** очистить фильтры; исходный URL до действия пользователя не переписывать. Не показывать выдачу как применённую, не подменять её нефильтрованной.
3. Для `sort` из утверждённого набора — делать реальный API запрос. Неизвестный sort / некорректный page — явное контролируемое validation state согласно текущему API и UX, без тихой подмены.
4. Для обычных URL без фильтров — серверная сортировка и пагинация. При изменении сортировки UI учитывать сброс `page` в 1, **только если** таково уже существующее пользовательское поведение; иначе зафиксировать несовместимость и согласовать. Не менять SEO canonical каталога автоматически без проверки существующих правил.

Текст временного состояния — публичный **на английском**; использовать существующие компоненты сообщений, без редизайна. Предлагаемая формулировка: `Filters are temporarily unavailable. Clear filters to view products.` — это предложение, а не обязательный новый дизайн. Кнопка Clear filters может удалять **только** фильтрующие параметры, сохраняя `sort` и `page` по согласованной существующей семантике; никакой автоматической очистки URL.

## 3. Порядок продолжения Codex (после Checkpoint A)

**B — API adapter:** проверить фактическую сигнатуру `category`, `perPage`, пагинации и форму DTO в Laravel; реализовать typed server-only client/mapper и тесты price/null, errors, canonical/media. Сохранить все текущие ручные изменения.

**C — страницы:** подключить catalog/list/detail и home featured; related по primary category; проверить mismatch redirect, SEO, изображения, empty/error states. Не менять публичную структуру/CSS. Для `/solutions`, `/cart`, `/search` оформить честную матрицу runtime dependencies и остановиться при указанном выше риске, требующем решения владельца.

**D — URL state:** реализовать утверждённые sort values, redirect `featured → newest`, явное недоступное состояние для старых и новых фильтров; не начинать BE-08.5.4.

**E — тестирование:** через Docker Compose согласно `AGENTS.md`; тестовая БД только `potsandplanters_test`, без миграций/seed в dev/production. Выполнить релевантные frontend unit/integration tests, typecheck, production build, `git diff --check`, SSR smoke на доступной тестовой среде. Если нет разрешённой безопасной тестовой среды для SSR — честно отметить `NOT RUN`. Не объявлять smoke пройденным без фактического запуска.

## 4. Обязательные сценарии приёмки

- `/shop` и category: API-only products, корректная пагинация; сортировки `newest`, `name-asc/desc`, `price-asc/desc`, `NULL` prices last (backend-owned).
- `?sort=featured&page=2&material=...` → явный redirect на `sort=newest` с сохранением `page` и `material`, затем **сообщение о недоступном фильтре**, не mock и не нефильтрованная выдача.
- `?material=...`, `?color=...`, `?size=...`, `?usage=...`, `?filter[code]=...`: ни silent drop, ни успешная нефильтрованная выдача. Clear filters — осознанное действие.
- Главная: максимум 8 новейших опубликованных товаров, меньше 8 — без заполнения mock; 0 — корректное пустое состояние; outage — явная ошибка.
- Related: до 4 других товаров primary category, без текущего UUID и mock; 0 — секция отсутствует; outage не выдаётся за 0.
- Detail: API `canonicalPath`, secondary category links, сохранённые legacy routes и mismatch redirect, `noindex,follow`, ручные meta/OG, корректный HTML/ALT.
- `priceAed=null` → `Price on enquiry`, строковая точность цены сохраняется; отсутствующие ready images → placeholder.
- API 404 / 422 / 503, empty 200 различаются; нет mock fallback на включённых маршрутах.
- `/solutions`, `/cart`, `/search`: документированные фактические зависимости и действия; никакой несанкционированной активации Enquiry или изменения persistence.
- Тесты, typecheck, build, доступный SSR smoke и git diff check документированы с точными командами и результатами.

## 5. Запреты и условие остановки

Не менять Laravel/Filament/DB, миграции, production, Nginx, SEO indexation, утверждённый стек, публичный дизайн; не рефакторить незатронутые модули; не переформатировать ручные Tabs в `ProductResource.php`; не выполнять BE-08.5.4/5.5 и BE-09. Не удалять незакоммиченные изменения. Не объявлять модуль принятым по одним автотестам.

**Остановиться до правок**, если выяснится, что согласованное поведение невозможно реализовать без изменения этих границ (например, активный mock Add to Enquiry в `/solutions` или невозможность честно отделить cart). Предоставить минимальные варианты и последствия, не выбирать самостоятельно.
