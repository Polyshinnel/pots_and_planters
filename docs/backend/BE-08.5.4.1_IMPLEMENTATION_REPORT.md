# BE-08.5.4.1 — Laravel Product API Filters Extension

**Status:** implementation ready for owner acceptance. No production database or migration was used.

## Read-only audit

- `GET /api/v1/products` already owns visibility, sorting, pagination, typed filter validation, category-scoped attribute eligibility, and facet aggregation.
- Before this change, filters required `category`, global requests returned `facets: []`, and numeric facets encoded extrema as two synthetic options with the same count.
- Category facet eligibility remains the configured category ↔ Attribute relation. Global eligibility is an active, filterable Attribute assigned to at least one Product Type. Inactive options are still excluded.
- The repository had extensive unrelated uncommitted changes before this task. They were preserved. `backend/routes/api.php` was already modified to register Product Read API routes and was not changed for this task.

## Implemented contract

- `filter[code]` now works both globally and with `category=<slug>`. Category scope keeps its explicit category filter allowlist; global scope resolves only globally eligible Attributes.
- The existing typed grammar and query behavior are reused: OR among values within one Attribute, AND across Attributes; exact text and decimal values, inclusive numeric bounds, and exact `true`/`false` boolean values.
- Products still pass through the same public visibility query before filtering, sorting, counting, pagination, and facet aggregation. Facet option counts remain distinct visible products after all active filters.
- Global facets include eligible Attributes across Product Types. Their `displayType` is derived from the Attribute type (`values`, `range`, `boolean`, `options`, `multi_options`). No legacy query mappings were added.
- Non-numeric facets retain `options: [{value,label,count}]`. Numeric facets now return actual decimal extrema as `min` and `max`; they do not include synthetic options or counts:

```json
{"code":"height","label":"Height","type":"number","displayType":"range","min":"0.000000","max":"20.000000"}
```

When no visible filtered product has a numeric value, both extrema are `null`. Existing category responses use this same numeric facet representation.
