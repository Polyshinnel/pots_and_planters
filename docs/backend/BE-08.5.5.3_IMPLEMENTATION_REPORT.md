# BE-08.5.5.3 — Laravel Product/Cart Enquiry Submit & Server Snapshots

**Статус:** реализация и автоматические проверки завершены; ожидается приёмка владельца. Product/Cart публично отключены.  
**Дата:** 10 ноября 2026

## Итог

В существующий `POST /api/v1/enquiries` добавлены `product_enquiry` и `cart_enquiry` с явным `apiVersion: 2`. Product identity — только UUID `products.public_id`; сервер повторно проверяет видимость на submit, сохраняет серверные snapshots и создаёт item rows, outbox и idempotency key в одной DB transaction. Contact и Catalogue Download продолжают использовать прежний контракт BE-07.

Никаких изменений Next.js, Solutions, Product Resolve API, публичного дизайна, production/staging или Telegram доставки не выполнялось. Уже имевшиеся до начала работы изменения Product Resolve API и связанные незакоммиченные документы/тесты сохранены без перезаписи.

## Контракт и поведение

Product v2:

```json
{
  "type": "product_enquiry",
  "apiVersion": 2,
  "product": { "productId": "<products.public_id UUID>", "quantity": 1 },
  "name": "…",
  "phone": "…",
  "email": "…"
}
```

Cart v2 использует `items: [{ "productId": "…", "quantity": 1 }]`, от 1 до 100 уникальных UUID. Quantity — integer 1..999999. SKU и любые клиентские данные товара не принимаются; неизвестные ключи в товарной строке и top-level snapshot поля дают 422. Поля контакта/source и `Idempotency-Key` сохраняют BE-07 semantics.

В одной транзакции Product rows выбираются в UUID порядке и блокируются `FOR UPDATE`. Также по возрастанию ID блокируются Brand, Supplier и primary Category rows. После lock повторно проверяются published Product, published primary Category и active Supplier. При любой недоступной позиции вся заявка отклоняется с `422 products_unavailable` и безопасным списком входных UUID; частичные items/outbox не создаются. Эти блокировки сериализуют проверку с изменениями статуса Product, Supplier и primary Category; Product parent row также блокирует конкурентные изменения его primary category и Brand FK через обычное обновление Product. Отдельный конкурентный stress test не проводился.

Snapshot строится из сохранённых Product/Brand и переиспользует публичный `ProductListData`, включая canonical path и разрешённые публичные specifications. До генерации DTO выполняется batch eager load; тест на 100 позиций подтверждает ограниченное число SELECT. Цена хранится в `DECIMAL(15,4)` как decimal string/null, без преобразования в float. Исторические значения не зависят от будущих Product данных.

Успех возвращает существующий BE-07 envelope: `persisted`, `enquiryId`, `notificationStatus`; HTTP 201 для новой заявки и 200 для idempotency replay. Существующая idempotency схема обеспечивает replay без новых rows/outbox и 409 при несовпадающем payload. DB failure продолжает возвращать безопасный 503. Telegram не отправлялся во время тестов.

## Snapshot schema

Добавлена additive migration `2026_11_10_000000_add_product_snapshots_to_enquiry_items`:

| Column | Type | Nullable | Purpose |
|---|---|---:|---|
| `product_public_id` | UUID | yes | UUID товара на момент заявки |
| `brand_public_id` | UUID | yes | UUID бренда на момент заявки |
| `brand_name_snapshot` | varchar(255) | yes | историческое имя бренда |
| `unit_price_aed` | DECIMAL(15,4) | yes | цена либо null |
| `currency` | CHAR(3) | yes | AED |
| `availability_snapshot` | boolean | yes | публичен в момент проверки |
| `snapshot_at` | timestamp | yes | время snapshot |
| `product_snapshot` | JSON | yes | разрешённый ProductListData для исторического отображения |

Существующие `product_identifier`, `sku_snapshot`, `quantity`, `position` сохранены. Новые колонки nullable, поэтому старые enquiry item rows читаются без backfill. Индекс `product_public_id` добавлен. `down()` удаляет только добавленные поля и индекс; rollback в этой работе не выполнялся.

## Filament, Telegram и flags

Filament отображает исторические Brand, SKU, Product name, quantity и цену из item snapshot; null цена выводится как `Price on enquiry`. Telegram formatter использует те же сохранённые поля и не ищет текущий Product.

| Backend setting | Environment variable | Default | Current public state |
|---|---|---:|---|
| `enquiries.product_enabled` | `PRODUCT_ENQUIRIES_ENABLED` | false | disabled |
| `enquiries.cart_enabled` | `CART_ENQUIRIES_ENABLED` | false | disabled |

Флаги независимы от Contact/Catalogue и друг от друга. При выключенном флаге API отвечает `404 feature_unavailable`; backend feature tests могут включать нужный флаг изолированно через test config. В Compose environment новые переменные не заданы, значения остаются выключенными. Существующий frontend dev flag не менялся и не открывает backend submit.

## Ограничения и приёмка

Изменение статуса Product, Supplier и primary Category сериализуется с submit через InnoDB row locks; lock coverage проверена по схеме и коду, но многопоточный race harness не запускался. Вторичные категории не участвуют в доступности и не блокируются, как и в существующем visibility scope.

BE-08.5.5.3 готов к ручной приёмке. Product/Cart flags выключены. После приёмки владелец может отдельно решить вопрос их активации; BE-08.5.5.4 автоматически не начинать.
