# BE-08.5 — Product API Contract v1 (утверждённая редакция)

**Статус:** архитектурный контракт утверждён владельцем 2026-11-09 по решениям в переписке. **Реализация не начиналась.** Основа: `BE-08.5.1_AUDIT_REPORT.md`, `BE-08.5.1_API_CONTRACT_PROPOSAL.md`, `BE-08.5.1_IMPLEMENTATION_PLAN.md`. При расхождении с кодом Codex обязан сначала описать расхождение; не менять согласованную семантику молча.

## 1. Область и границы

- Только read-only `GET /api/v1/products` и `GET /api/v1/products/{slug}`. Текущие category/news/enquiry API не ломать.
- Не добавлять ProductVariant, не менять публичный Next.js, маршруты, SEO, дизайн, Nginx, старые 301/308, корзину и отправку заявок в BE-08.5.2.
- Публичные Product/Cart Enquiry остаются выключенными. Production deploy и миграции требуют отдельного разрешения.
- Публичные ID — UUID `products.public_id`; никогда не отдавать DB PK, private media path, supplier internal data или технические токены.

## 2. Endpoints и HTTP

### GET /api/v1/products

`200 {"data": ProductListDto[], "meta": PageMeta, "facets": FacetDto[]}`; пустой список — `200` с `data:[]`. `facets:[]` для глобального списка без категории. `category=<slug>` выбирает опубликованную категорию; товары учитываются и по secondary association. Неизвестная/неопубликованная категория — `404 category_not_found`.

Параметры: `page` положительное целое, default 1; `perPage` целое 1–48, default 12. Валидная страница за пределом выборки — пустой массив без clamp. `sort=newest|name-asc|name-desc|price-asc|price-desc`, default `newest`; `featured` не поддерживать. `newest`: `created_at DESC, name ASC, public_id ASC`; сортировка по имени и цене с устойчивым `public_id` tie-break, `NULL` цены всегда в конце, SQL decimal precision без float.

### GET /api/v1/products/{slug}

`200 {"data": ProductDetailDto}`; глобальный текущий slug, не category path. Неизвестный, draft, archived, скрытый Supplier, неопубликованная Primary Category — одинаковый `404 product_not_found`. Возвращать только актуальный `canonicalPath` от `ProductUrlResolver`, без HTTP redirect/изменения alias registry. Исторические alias и Next 308 не перерабатывать до BE-09.

### Публичная видимость

`Product.status=published`, опубликованная Primary Category, активный Supplier. Для выдачи в категории — также опубликованная category association. Неактивность Brand, Product Type, Series, Attribute, Option сама по себе **не скрывает Product**. Сохранённые значения/labels inactive Attribute/Option отображать в detail/card; inactive определения и варианты не предлагать для нового выбора в фильтрах. Не отдавать черновые товары или данные из private media.

## 3. DTO (обязательные публичные поля)

```ts
type ProductSpecificationDto = { code: string; label: string; value: string; displayText: string };
type ProductListDto = {
  id: string; slug: string; sku: string; name: string;
  brand: { id: string; name: string };
  priceAed: string | null; currency: 'AED';
  categoryIds: string[];
  primaryCategory: { id: string; slug: string; name: string; path: string };
  canonicalPath: string;
  cardImage: { url: string; alt: string } | null;
  cardSpecifications: ProductSpecificationDto[];
  cardSpecificationsText: string;
};
type ProductDetailDto = ProductListDto & {
  series: { id: string; name: string } | null;
  descriptionHtml: string | null;
  seo: { title: string; description: string | null; ogImage: string | null; robots: 'noindex,follow' };
  images: Array<{ url: string; cardUrl: string | null; thumbUrl: string | null; alt: string; order: number; isMain: boolean }>;
  attributes: ProductAttributeDto[];
};
type ProductAttributeDto = {
  id: string; code: string; label: string; shortLabel: string | null;
  type: 'text' | 'number' | 'boolean' | 'select' | 'multiselect';
  value: string | boolean | string[] | null;
  unit: string | null;
  options: Array<{ value: string; label: string }>;
};
type PageMeta = { page: number; perPage: number; total: number; lastPage: number; sort: string };
type FacetDto = {
  code: string; label: string;
  type: 'text' | 'number' | 'boolean' | 'select' | 'multiselect';
  displayType: 'values' | 'range' | 'boolean' | 'options' | 'multi_options';
  options: Array<{ value: string; label: string; count: number }>;
};
```

Числовые атрибуты и `priceAed` — точные decimal strings, без float. `false`, `0` и `0.000001` не теряются. Пустые typed values и неприменимые optional attributes не сериализуются как заполненные; `null` сохранять для явно nullable DTO-полей. Select/multiselect используют стабильные option values и сохранённые labels. `descriptionHtml` — только HTML после существующей серверной санитизации. Не генерировать SEO description из Product Description.

`cardSpecifications[]` и `cardSpecificationsText` формируются одним `ProductCardSpecificationsFormatter` с сохранением порядка `card_display_attribute_ids`, short label, numeric unit и правил пустых значений. Публичный Next.js formatter пока не менять.

## 4. Изображения

Только `ready` MediaAsset и физически существующие public WebP variants. Для `cardImage`: card → thumb → `null`. Для gallery: full → card → thumb → исключить изображение, если ни одного варианта нет. `cardUrl` и `thumbUrl` могут быть `null`, если соответствующий вариант отсутствует; `url` всегда рабочий выбранный variant. ALT — override или существующий безопасный fallback; порядок gallery и main сохраняются. Отсутствие изображения = честный frontend placeholder, не private original и не mock.

## 5. SEO и кэш

`canonicalPath` — относительный путь `/shop/{primary-category-slug}/{product-slug}` от существующего resolver; публичный host задаётся конфигурацией frontend. `seo.title` — ручной override либо Product name. `seo.description` — только ручной override или `null`; не генерировать автоматически. `seo.ogImage` — готовый manual OG override, иначе готовый main image, иначе `null`. `seo.robots='noindex,follow'` до отдельного разрешения владельца на index. `Cache-Control: no-store` для обеих GET routes.

## 6. Фильтры: утверждённая семантика

Только в category scope. Формат `filter[code]` со stable Attribute code. Опции — stable `attribute_options.value`; boolean — `true|false`; text — точное сравнение; number — точное decimal сравнение или inclusive range `filter[code][min]` / `[max]` (каждая граница опциональна, обе вместе допускаются; min > max → 422). Не использовать float. OR между значениями одного атрибута, AND между разными атрибутами. Сначала SQL-фильтрация, затем сортировка и pagination.

Facet eligibility: опубликованная категория ↔ Attribute config, глобальный `is_filterable`, активный Attribute, совместимый `display_type`, связь с Product Type. Inactive options/definitions не предлагать как новые варианты. Counts вычислять **после всех активных фильтров** (conjunctive), distinct опубликованные видимые Product, включая secondary category; показывать только доступные варианты с count > 0. `false`/`0` считаются значениями, не пустотой. Неизвестные/неактивные/не настроенные filter keys/values → 422, не игнорировать молча.

Старые query keys `material`, `color`, `size`, `usage`: поддержать только через явную карту совместимости, привязанную к реальной конфигурации категории. Не выдумывать сопоставления или данные; если mapping неоднозначен, конфликтует с `filter[code]` либо невалиден — 422. Пока карта не подтверждена реальным frontend-кодом/категориями, не объявлять поддержку конкретного legacy value успешной. Совместимость URL окончательно проверяется в BE-08.5.4; в BE-08.5.2 реализовать согласованную backend grammar и тестируемый механизм mapping, не придумывая mappings.

## 7. Ошибки

Новые Product endpoints используют:

```json
{"error":{"code":"product_not_found","message":"The requested product was not found.","requestId":"<opaque-request-id>"}}
```

Для `422` добавить `error.errors` (field → array of human-readable messages). Для неизвестной категории — `category_not_found`; при инфраструктурной недоступности — `503 service_unavailable`, без SQL/stack/private paths. Все публичные сообщения — на английском. Request ID непрозрачен, логируется безопасно. Существующие category/news/enquiry error responses не менять. Empty `200` ≠ `404` ≠ `503`.

## 8. Отложенные решения, не блокирующие BE-08.5.2

- Cart storage: line identity = Product public UUID; недоступную позицию не удалять молча; submit отклоняет её с понятной ошибкой. Серверные authoritative snapshots, точная цена, payload versioning и активация — BE-08.5.5, отдельная приёмка.
- Home FeaturedProductsSlider: нет утверждённого `featured` source/flag; не придумывать, решение перед BE-08.5.3.
- Legacy URL/301: BE-09 Nginx после реальной миграции; не реализовывать сейчас.
- Не вводить индексы без SQL/EXPLAIN evidence и отдельного review.

## 9. Критерии приёмки контракта

Contract tests подтверждают JSON shape, видимость, category secondary, сортировки, nullable price, decimal precision, typed values, готовые media, SEO/noindex, sanitized HTML, errors/no-store, отсутствие N+1 и утечки внутренних данных. Результат BE-08.5.2 — только backend API + отчёт. Публичный Next.js не подключать до отдельной приёмки.
