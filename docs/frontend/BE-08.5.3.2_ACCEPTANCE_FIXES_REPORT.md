# BE-08.5.3.2 — Acceptance Fixes & SSR Verification

**Status: READY FOR ACCEPTANCE.** The two requested HTTP behaviors were fixed with frontend routing changes only. No Laravel/API code, database records, seeds, migrations, middleware, Proxy, or Nginx interception were added. Existing unrelated working-tree changes were preserved.

## Changes

1. **Nested missing Product returns HTTP 404 before streaming.** The `/shop` and `/shop/[category]` listing pages and their existing loading UI now live under the route group `frontend/src/app/shop/(catalog)/`. The `loading.tsx` boundary is scoped to those listing routes. `/shop/[category]/[slug]` stays at its existing public URL outside that group, so the Product lookup and `notFound()` complete before a shell is streamed. The loading UI itself was moved intact; the public path and page structure did not change.
2. **`sort=featured` uses an early HTTP redirect.** `frontend/next.config.ts` now applies temporary redirects to `/shop` and `/shop/:category` only when the `sort` query value is `featured`, replacing it with `newest`. The existing in-render redirect was removed from `CatalogPage`; normalization now occurs before React route rendering. Redirect rules do not match nested Product paths.

Files changed for the fixes:

- `frontend/next.config.ts`
- `frontend/src/components/catalog/CatalogPage.tsx`
- moved `frontend/src/app/shop/page.tsx` to `frontend/src/app/shop/(catalog)/page.tsx`
- moved `frontend/src/app/shop/[category]/page.tsx` to `frontend/src/app/shop/(catalog)/[category]/page.tsx`
- moved `frontend/src/app/shop/loading.tsx` to `frontend/src/app/shop/(catalog)/loading.tsx`
- removed the redundant `frontend/src/app/shop/[category]/loading.tsx` re-export that previously streamed nested Product detail

`frontend/next.config.ts` already had a dirty `allowedDevOrigins` change before this task; it was retained. No product data source, fallback, SEO mapping, CSS, page copy, cart, Solutions, API contract, or public URL was changed.
