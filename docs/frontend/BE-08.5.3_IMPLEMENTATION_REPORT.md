# BE-08.5.3 — Next.js Product API Integration

**Status:** implementation complete; awaiting owner acceptance. No production deployment was performed.

## Scope and decisions

- Connected `/shop`, `/shop/[category]`, `/shop/[category]/[slug]`, legacy `/product/[slug]`, and homepage Featured Products to the approved Laravel Product Read API.
- Product lists use `GET /api/v1/products`; detail uses `GET /api/v1/products/{slug}`. Categories remain sourced from Categories API.
- Featured Products requests up to eight newest published products (`sort=newest&perPage=8`). The approved section title and slider layout remain. The source is newest records rather than an editorial featured flag.
- Related Products requests at most five newest products from the current product's primary category, removes the current public UUID, then displays up to four. It does not load later pages to fill a short result.
- Supported server sorting is `newest`, `name-asc`, `name-desc`, `price-asc`, and `price-desc`. Legacy `sort=featured` uses Next.js `redirect()` to `sort=newest`, preserving the other query values. Invalid sort/page values show a validation message.
- Legacy filters (`material`, `color`, `size`, `usage`) and `filter[code]` are not sent to the API. They keep their URL and show “Filters are temporarily unavailable” with an explicit Clear filters action. That action removes filter parameters and retains sort/page.
- Product details' Add to Enquiry action is disabled for API Product records until BE-08.5.5. The existing layout remains and an English message explains the temporary unavailability. No handler or enquiry-store call remains on this path.
- On `/solutions`, both fixture Product Add actions are disabled and their write handlers/store imports were removed. The existing Solutions data/repository remains fixture-backed and is not connected to Product API.

## API DTO mapping

Added a server-only typed adapter in `frontend/src/lib/catalog/products.server.ts`, using the existing `serverApiFetch` and `API_INTERNAL_URL` with `no-store`:

- Public Product UUID maps to UI `Product.id`; SKU remains separate.
- `priceAed` remains `string | null`. Formatting groups the integer portion without converting API decimal strings to floating point; `null` displays “Price on enquiry”.
- Category IDs, primary category slug, API `canonicalPath`, ordered card specifications, `cardSpecificationsText`, and ready media URLs map to the existing UI models. A missing image uses the existing image placeholder.
- Detail description HTML is passed through from the API's sanitized DTO. SEO title/description/OG/robots use the API detail DTO; `noindex,follow` is retained.
- Detail `404` becomes Next `notFound()`. Other API errors propagate to page error boundaries; Product list failures are not converted to empty results or fixture data. Empty list `200` remains an empty result.

The actual test-database Product API responses available during SSR smoke were empty:

```json
{"data":[],"meta":{"page":1,"perPage":8,"total":0,"lastPage":1,"sort":"newest"},"facets":[]}
```

No real Product DTO was available in `potsandplanters_test` for a populated SSR example. Adapter tests use clearly synthetic DTOs to verify exact decimal/null/media/SEO mapping; they are not production Product data.

SSR smoke used a temporary Laravel server configured with `DB_DATABASE=potsandplanters_test` and a production standalone Next server configured with `API_INTERNAL_URL=http://backend:18001/api`. Only GET requests were made; no seeds, migrations, or database writes were performed. Both temporary servers were stopped afterward.

- `/` — 200; no old fixture Product appeared in rendered HTML; Featured empty state rendered.
- `/shop` — 200; API empty state rendered (`0 products`); no fixture Product appeared.
- `/shop?sort=featured&page=2&material=ceramic` — streamed Next response contained redirect target `/shop?sort=newest&page=2&material=ceramic` and `NEXT_REDIRECT` digest code 307. Next streamed this as HTTP 200 with a meta refresh, rather than a raw HTTP Location response.
- `/shop?material=ceramic&sort=name-asc&page=3` and `/shop?filter[height]=100` — 200 with explicit temporary-filter state; no unfiltered result was presented.
- `/shop?sort=bogus` — 200 with explicit invalid sort/page alert.
- `/product/no-such` — HTTP 404 from Product API unknown slug.
- `/shop/outdoor-pots/no-such` — Next's streamed response was HTTP 200 in this smoke run; the Product API returned 404. The route calls Next `notFound()`, but a streamed App Router response can commit HTTP 200 before that result. This status behavior remains a manual acceptance point; no middleware/proxy status rewrite was introduced because that would alter the agreed route behavior.

The test DB contains no published categories or products. Therefore populated category/detail/secondary-category SSR, canonical mismatch redirect, real media/ALT/OG, API outage rendering on populated detail, and dynamic appearance without rebuild could not be exercised in SSR. DTO tests and error-boundary implementation cover the locally testable mappings; SSR for those populated cases is **NOT RUN**. The test DB's empty result is not evidence of populated Product behavior.
