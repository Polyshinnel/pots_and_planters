## Read-only контрактный checkpoint

Проверены `AGENTS.md`, `docs/common/PROJECT_CONTEXT.md`, `docs/common/ROADMAP.md`, отчёты BE-08.5.4.1 и BE-08.5.3.3, текущие незакоммиченные изменения, `ProductReadController`, `ProductReadApiTest`, DTO, Next.js adapter, каталоговые страницы и существующий Mantine drawer.

- Дискретные значения передаются как `filter[code][]=value`; допускается и единичное `filter[code]=value`. Несколько значений одного кода — OR, разные коды — AND.
- Boolean сериализуется строками `true` и `false`; `false` — выбранное значение.
- Number exact допускает `filter[code]=decimal`; inclusive range передаётся как `filter[code][min]=decimal` и/или `filter[code][max]=decimal`. Backend принимает десятичные строки с максимум шестью знаками дробной части, включая `0`; порядок границ проверяется без float.
- Filter values URL-encoded стандартным `URLSearchParams`; повторные `[]` сохраняются.
- Facet DTO: `code`, `label`, `type`, `displayType`; дискретные типы имеют `options[{value,label,count}]`; number имеет строковые `min/max` либо `null`, без options/count. Facets ограничены активными filterable attributes и scope текущей категории либо всего каталога. Counts возвращает API.
- Неизвестный/недоступный код и некорректные значения дают API 422; инфраструктурная ошибка — 503. Пустой ответ сохраняет `facets: []`.
- `backend/config/product_filters.php` содержит пустой legacy mapping. Legacy `material/color/size/usage` не преобразуются и не отправляются как молча проигнорированные фильтры.
- Сортировка `featured` нормализуется существующим Next redirect 307 на `newest`; известные категории разрешаются API, неизвестные идут через `notFound()`.

## Реализация

- Расширены DTO типов каталога и server-only API adapter; в `/shop` и `/shop/[category]` передаются фильтры и используется ответ API с facets/counts.
- Добавлен URL parser/serializer для повторных опций, boolean false, exact text и decimal ranges; пользовательские не-фильтровые query параметры сохраняются при сортировке, пагинации и изменении фильтра. Изменение фильтра/сортировки устанавливает страницу 1.
- Панель и mobile drawer используют текущие компоненты и стили. Дискретные значения показывают серверный count; выбранное значение, исчезнувшее из текущего набора options, остаётся доступным для снятия. Number inputs используют строки и API min/max как placeholder; если обе границы `null`, range UI не создаётся.
- URL с legacy filters остаётся явным unsupported state с действием очистки. Некорректная грамматика/range получает явное состояние и reset. API 422 предоставляет объяснение и очистку фильтров; 503 сохраняет отдельный error state с повтором.
- Enquiry actions и нецелевые модули не менялись в рамках BE-08.5.4.2. Laravel, БД, дизайн, SEO и routing source не менялись.

## Ограничения и передача

Фактические option counts, доступные значения и диапазоны зависят от наполнения API/категорий; клиент не подменяет их fixture-данными. Legacy URLs требуют отдельного подтверждённого mapping, сейчас они предлагают только явную очистку. HTTP status 200 для streamed not-found в изолированном Next SSR зафиксирован для рассмотрения при приёмке и не исправлялся в рамках ограничений на SEO/routes.
