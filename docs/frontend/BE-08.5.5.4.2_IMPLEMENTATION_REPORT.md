## Changes in this stage

- `frontend/src/lib/enquiry/product-resolve.client.ts`: one UUID-only batch request, no request for an empty list, browser `no-store`, 12 second timeout, strict whole-response validation and positional identity checks. Any HTTP, network, timeout or invalid-response failure rejects the batch. No SKU/slug lookup or fallback is used.
- `frontend/src/components/enquiry/ResolvedCart.tsx`: hydrates v2 before display; renders available items from the API DTO and unavailable items distinctly; keeps quantity read-only; offers Retry on resolve failure. Shows legacy rows in a separate section. Corrupt and unavailable storage states are explicit and never rendered as empty. No subtotal, total, Product/Cart CTA or submit form is shown.
- `frontend/src/lib/enquiry/store-v2.ts`: adds a narrowly scoped `removeLegacyAt(sourceIndex)` operation and preserves the v1 raw snapshot in memory. It rereads and compares the exact v1 bytes before removal, validates the whole envelope, removes only the selected source index, writes a version 1 envelope even when the last row is removed, reads it back, and updates UI state only after success. A stale snapshot, malformed/unknown envelope or write failure is not treated as success.
- `frontend/src/app/cart/page.tsx` and `frontend/src/components/layout/CartEntry.tsx`: Cart page and header badge/preview now read v2 and surface storage diagnostics without resolving through the mock catalogue.
- `frontend/tests/product-resolve.test.cjs` and `frontend/tests/enquiry-store-v2.test.cjs`: batch contract, response validation, exact decimal display, atomic errors, targeted duplicate-SKU deletion, preservation on storage failure, and stale snapshot coverage. The v2 store/test files were already present as untracked work before this task; their implementation was extended in place.

The only resolve input is `item.productId` from v2. Successful `available` responses require `response.id === product.id === requested UUID`, valid DTO fields and the original response order. `unavailable` is accepted as a separate item status. Every other outcome is `resolve_error`, leaves storage unchanged and exposes a Retry action. Prices remain decimal strings and are formatted without float arithmetic; `null` displays `Price on enquiry`. Only the DTO card image URL is used, with a placeholder when null.

Legacy IDs, even UUID-shaped IDs, are never sent to resolve and rows are never matched by SKU. Removal uses the displayed source index plus an exact raw-snapshot equality check; all other rows keep their order. Malformed, unknown-version or stale v1 data cannot be removed through the UI. A failed write leaves the displayed row intact and reports failure.
