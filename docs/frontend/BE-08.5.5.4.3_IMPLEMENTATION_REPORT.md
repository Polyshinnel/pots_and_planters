## Реализация

- Отдельный frontend gate `NEXT_PUBLIC_PRODUCT_ENQUIRIES_ENABLED` проверяется для Product add и Cart edit. По умолчанию переменная отсутствует/false; `true` задаётся только frontend service в `compose.dev.yaml`. Staging/production Compose и Docker build args не менялись.
- Product details перед каждым добавлением вызывает существующий `POST /api/v1/products/resolve` ровно для UUID из `Product.id`; запись выполняется только при `status: available`. Ошибка/недоступность не меняет корзину. Один выполняющийся запрос блокирует повторный click; последующее отдельное добавление того же UUID объединяется v2 store и прибавляет quantity.
- V2 envelope/key, пределы и typed failures не менялись. SKU и slug не участвуют в cart identity. Store сохраняет порядок остальных UUID, проверяет storage read-back и сохраняет отдельную v1 секцию.
- Cart показывает controls quantity +/- для доступных строк и ручное удаление каждой v2 строки, включая unavailable. Unavailable строки не удаляются автоматически и не меняют quantity. Retry resolve не меняет storage; изменение quantity не вызывает повторный resolve, так как он зависит от набора UUID.
- Header preview восстановлен с API изображением, названием, quantity controls и remove. Убрана текстовая строка со счётчиками current/older items. При открытии preview выполняется один UUID batch resolve; повторное разрешение зависит от набора UUID, а не quantity. История Git показывает, что прежние `EnquiryItems` и `EnquiryTotals` в `CartEntry` были заменены текстовой сводкой в HEAD commit `9fefac6` (`feat: Implement product resolution and enquiry management for v2`); это было сокращение UI при BE-08.5.5.4.2.
- Страница `/cart` возвращена к прежней утверждённой двухколоночной композиции с benefits, selection, project help и quotation panel. Product rows, изображения, quantity, удаление и суммы используют только API Resolve и v2 UUID. Форма и CTA отправки видны как disabled; submit integration не включалась.
- Edit controls отключены при выключенном gate, corrupt/unavailable storage или непостоянном состоянии. Ошибки записи показываются пользователю. Cart/header продолжают использовать существующую v2 подписку и storage events; badge сохраняет ранее принятую семантику суммарного quantity, включая legacy v1.
- Product submit не подключён: `ProductEnquiryForm` по-прежнему передаёт только optional adapter, а submit CTA остаётся disabled. В новых Product/Cart компонентах нет `submitEnquiry` или POST `/api/v1/enquiries`. Backend `product_enabled` и `cart_enabled` имеют default `false`; их конфигурация не менялась.
- Solutions, Contact/Catalogue формы, Laravel API/backend и публичные маршруты не менялись.
