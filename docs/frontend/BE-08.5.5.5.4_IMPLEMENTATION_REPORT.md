## Реализация

Единственный рабочий источник корзины — store-v2.ts с UUID/quantity. Удалены чтение v1, legacy parser/state/removal и legacy section. Старый localStorage namespace не читается, не переносится и не перезаписывается: неизвестные пользовательские байты автоматически не удаляются. Mock позиции не отображаются, не подсчитываются и не отправляются. Удалены неиспользуемые mock Cart store.ts, lines.ts, submission.ts, EnquiryItems.tsx. Старый EnquiryCheckout теперь ссылается на актуальную корзину. Solutions сохранён, его guard проходит. Технические имена store-v2/submit-v2 и apiVersion:2 сохранены для действующего Laravel контракта; параллельных форматов хранения в рабочем сценарии нет.

Cart form использует POST /api/v1/enquiries и Idempotency-Key через существующий shared adapter. Payload: type=cart_enquiry, apiVersion=2, items=[{productId: Product UUID, quantity: сохранённое число}], name, phone, email, company из Company / Project name, message из Comments, source={pagePath:/cart, placement:cart}. SKU, snapshots, names, images, prices отсутствуют. Контакты проходят общую валидацию с phone max 64, комментарий max 5000; backend field errors показываются у полей.

На submit создаётся отдельный in-memory snapshot. Resolve выполняется одним batch запросом; error или unavailable блокирует весь submit, строки сохраняются. Backend unavailable UUID передаются в Cart rows и показываются в сообщении. Pending блокирует повторный submit и локальные controls. Изменения другой вкладки не меняют payload; после успеха сравнивается актуальный store со snapshot. Автоматической очистки нет.

Используется отдельный cart_enquiry attempt slot. Pending metadata/read-back, прежний key после uncertain outcome, явное подтверждение changed/expired/conflict и persisted reference обеспечиваются существующим manager. Persisted snapshot повторно не отправляется: reference восстанавливается при повторе submit после reload, без resolve/fetch. Контакты после reload не восстанавливаются, PII в sessionStorage не сохраняются. В UI показаны validation, resolve, unavailable, conflict, storage failure, rate limit, uncertain outcome и success/reference. Privacy notice без checkbox сохранён; текст политики уточнён для UUID.

Read-only tinker проверил фактический API runtime: database=potsandplanters; cart_enabled=false; Telegram notifications=true; token_present=true; enabled recipients=1. Секреты и chat IDs не выводились. Compose ps подтвердил работающий horizon, backend, scheduler, db, redis, nginx, frontend. Безопасная изоляция API отсутствует. По разделу 9 ТЗ Cart frontend/backend flags оставлены OFF, API smoke пропущен. Product submit local gate сохранён. Staging/production не менялись, реальные заявки и сообщения не создавались. Laravel source текущим этапом не менялся; Laravel tests не запускались.

Остановка до ручной приёмки владельца. Для функциональной приёмки отправки необходим изолированный API runtime с отключёнными реальными Telegram получателями.

## Уточнение владельца и локальная активация

Владелец подтвердил, что обычная локальная potsandplanters и настроенный Telegram чат разработчика предназначены для этой проверки, и разрешил включить корзину в существующей среде. Предыдущее ограничение активации снято этим указанием. В compose.dev.yaml включены CART_ENQUIRIES_ENABLED=true и NEXT_PUBLIC_CART_ENQUIRY_SUBMIT_ENABLED=true. База и Telegram настройки сохранены. Применение выполнено пересозданием локальных backend/frontend контейнеров. Автоматические реальные submit-заявки при активации не отправлялись.

## Общая конфигурация приложения

По следующему указанию владельца все шесть feature flags включены в корневом .env и шаблонах окружения. Основной compose.yaml передаёт PRODUCT_ENQUIRIES_ENABLED/CART_ENQUIRIES_ENABLED PHP сервисам и все четыре NEXT_PUBLIC флага как frontend build args; defaults=true. Dockerfile принимает все четыре аргумента до next build, defaults=true. Dokploy наследует эту конфигурацию. Проверка итогового Compose с compose.dokploy.yaml подтвердила true у всех шести флагов. Удалён устаревший комментарий о выключенных формах. Для уже опубликованного frontend образа требуется rebuild/redeploy: NEXT_PUBLIC значения встраиваются в JavaScript при сборке. Удалённый deployment в этой сессии не выполнялся.
