# FE-10.1 — Interactive Solutions Gallery (demo content, admin-ready)

## Goal
Turn the existing `/solutions` editorial landing page into a B2B inspiration-to-enquiry workflow: space → designed scene → identified products → editable specification → enquiry cart. Build the frontend against a typed, replaceable data source suitable for future Laravel 13 API and Filament management. This is a staging implementation: demonstrative content is allowed but must never be presented as an actual completed client project.

## Read before editing
Inspect existing `/solutions`, shared design system, responsive conventions, catalogue/product mock source, product detail routes, FE-05 cart store/actions, and existing image/gallery tools (Swiper/Fancybox if already present). Preserve manual styling changes. Do not invent paths or duplicate cart stores. Confirm available local image-generation capability before assuming images can be generated.

## 1. Page and interaction
- Keep existing editorial hero, five solution categories, navigation anchors and final B2B CTA. Integrate interactive galleries into these sections without turning the page into a wall of duplicated copy.
- Categories: Hospitality & Hotels; Restaurants & Cafés; Offices & Commercial Spaces; Villas & Residential Projects; Retail & Public Spaces. Stable slugs/anchors.
- Each category supports 0..N scenes (a scene is a designed interior/exterior composition). Provide at least **two complete demo scenes** across different categories, e.g. `Contemporary Hotel Lobby` and `Restaurant Terrace`. Other categories must render gracefully with no scenes, using the existing editorial content and links to Collections; never show blank broken galleries.
- Scene selector/thumbnail cards, active scene gallery (1..N images), concise scenario description, numbered image hotspots, product specification panel, and actions `View Product`, `Add to Enquiry`, `Add Solution to Enquiry` (or `Add Selected to Enquiry`).
- For each hotspot, select/highlight the corresponding specification item. On desktop use a compact popover or side panel without obscuring the scene. On mobile prioritize the product list beneath the image, with clear active state; avoid tiny overlapping popovers.
- Support image gallery keyboard/touch navigation using existing tooling; avoid gesture conflicts with hotspot taps. If full-screen viewing is available, keep hotspots understandable or provide a separate image-only view.
- The entire composition can be added in one action with user-adjustable quantities per line. Reuse existing cart add/increment logic; deduplicate by actual product identity/SKU. Respect existing cart persistence, header badge and mini-cart. The scene's recommended quantity is an initial default, not a fixed order quantity.
- Do not claim that selecting a scene is a purchase or confirmed quote. Cart and checkout remain enquiry-based.

## 2. Demo content and images
- Create **two credible demo scenes** with at least one image each, preferably 2 images per scene if resources permit, visually consistent with the premium Pots & Planters brand. Clearly label scenes `Concept visualisation` or `Illustrative concept`, never `Completed project`, `Our project`, or named client installation.
- Codex should generate suitable images **only if a real image-generation tool is available in its environment**. Otherwise use properly licensed existing project assets or clear placeholders and report the missing images; do not claim that an image was generated. Do not silently use remote hotlinked images or assume a generative CLI exists.
- Demo product links/hotspots must refer only to actual products in the existing mock catalogue. However, unless the product is verifiably depicted in the generated/rendered scene, label it `Suggested product` / `Suggested alternative`, not `Product shown`. For truly exact product depictions, label `Featured product` and record explicit association. Do not imply a real SKU is visible in an image merely because it looks similar.
- Use real product names, SKU, image and detail URL from the existing product data source. Do not fabricate SKU values or broken routes. A scene may use fewer hotspot products if exact valid products are unavailable.
- Optimize local images appropriately (Next/Image, dimensions, responsive sizing, modern format if feasible); avoid oversized payloads and layout shifts.

## 3. Admin-ready typed data contract
Create a clear typed model in a dedicated domain/data module (names adapted to repo conventions):

- `SolutionCategory`: `id`, `slug`, `title`, `intro`, `sortOrder`, `isPublished`.
- `SolutionScene`: `id`, `slug`, `categoryId`, `title`, `summary`, `isConcept`, `status` (`draft`/`published`), `sortOrder`, `coverImageId`, `images[]`, `items[]`.
- `SolutionImage`: `id`, `src`, `alt`, `width`, `height`, `sortOrder` (optional caption).
- `SolutionItem`: stable `id`, `productId` or canonical SKU referencing existing catalogue, `recommendedQuantity`, `sortOrder`, `matchType` (`exact`/`suggested`), optional display note.
- `SolutionHotspot`: stable `id`, `imageId`, `solutionItemId`, normalized `x` and `y` in [0, 1], `sortOrder`; optionally `label` for accessibility. Each hotspot references a product item in the same scene and an image in that scene.

Store hotspot coordinates normalized to the image content, **not pixel coordinates**. Render relative to the actual image rectangle with correct `object-fit`/aspect ratio so markers remain aligned on desktop/mobile; do not place hotspots on letterboxed padding. Ensure item quantities are positive integers and links resolve.

Build an adapter/repository boundary such as `getSolutionCategories()` / `getSolutionScenes()` (mock now, API later), without exposing mock arrays directly in JSX. Keep stable identifiers, predictable order, optional data handling and no hard dependency on Filament at frontend runtime.

For future phase 3, document intended Laravel/Filament responsibilities: CRUD categories/scenes, multiple images, product association from catalogue, quantity, hotspot placement per image, draft/publish, sort order, validation and API read endpoints. **Do not implement backend, migrations, Filament resources or API endpoints in this task.**

## 4. Interaction and accessibility
- Interactive hotspot is a real focusable button with accessible name (product and marker number), focus indicator, and keyboard activation. Active product state is reflected in image marker and list; no hover-only information.
- Support Escape to close any popover, appropriate outside-click handling, and no accidental navigation when selecting a marker.
- Respect reduced-motion settings; maintain readable contrast, image alt text, minimum usable touch targets and responsive behavior down to iPhone SE.
- On selecting a product, show name, SKU, dimensions/finish if available, quantity control, `View Product` and `Add to Enquiry`. Avoid showing fabricated dimensions/prices.
- For whole-solution add, clearly report which items were added and their quantities, and ensure repeat clicks have the expected additive behavior (no duplicated cart lines).
- If no scene image or no product is available, degrade gracefully; never crash or show broken clickable actions.

## 5. Scope boundaries
- Preserve existing Home, About, Catalogues, Contacts, Header/Footer and FE-05 cart behavior.
- Do not add new top-level routes unless necessary; existing `/solutions` and category anchors remain valid.
- Do not create a separate CMS, new checkout, new forms, or speculative admin UI.
- Do not install heavy libraries when existing Swiper/Fancybox/Mantine can serve the need.
- No invented client logos, testimonials, completed projects, exact-product image matches or business promises.
- All user-facing copy in English, consistent with the site.

## 6. Implementation sequence
1. Audit existing code, assets and cart API.
2. Define typed data model, mock repository and two sample scenes.
3. Prepare/create scene images and confirm what was actually generated versus reused.
4. Implement responsive scene selector/gallery, hotspots and specification list.
5. Integrate individual and whole-scene add-to-enquiry via existing cart actions.
6. Add error/empty-state handling and accessibility.
7. Validate and document the API/Filament handoff.

## 7. Acceptance tests
- `/solutions` retains its editorial structure and all five category anchors.
- Two demo scenes exist in different categories and are clearly labelled illustrative concepts.
- Images load correctly; image switches and scene switches preserve correct hotspot associations.
- Marker activation selects the correct item on desktop and mobile; keyboard access works.
- All linked product SKUs exist in the current catalogue and product links work.
- Changing recommended quantities works; individual and whole-scene additions update header badge, mini-cart and checkout, including after reload.
- Unknown-priced items remain `Price on enquiry`; totals never falsely imply a final price.
- Empty categories and missing images/items degrade gracefully.
- No fabricated claims that pictured products are exact unless supported.
- No horizontal overflow on narrow mobile; no unreadable hotspot overlay.
- TypeScript checks, lint (if configured), and production build pass. Report any pre-existing unrelated failures distinctly.
